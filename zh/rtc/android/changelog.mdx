> 本页根据 `rtc-android` 仓库的版本配置和提交记录整理。可通过 `RTCEngine.version()` 获取运行中的实际 SDK 版本。

### [2.0.29] - 2026.08.26

#### 变更

+ 将 `screenCapture` 分支合并入 `master` 分支。

### [2.0.28_audioOptimization.2] - 2026.08.26

#### 优化

+ FY 和 WS 流媒体引擎的外部麦克风上行新增 AEC、NS 硬件优先、软件兜底策略：两项能力独立探测和验证，平台效果未真正启用时自动回退到 WebRTC 软件处理，避免重复处理或处理缺失。

#### 变更

+ `RTCLocalAudioFrameEvent` 的 PCM 数据阶段随本版本的 AEC/NS 策略调整：平台 AEC/NS 已启用时包含对应平台处理；回退到 WebRTC 软件处理的项目，返回的是软件 APM 处理前数据。

### [2.0.28_audioOptimization.1] - 2026.08.26

#### 修复

+ 优化 FY 和 WS 流媒体引擎的外部麦克风推送到 WebRTC ADM 的桥接节拍，修复部分设备上行音频出现卡顿、断流、气泡音或类似丢帧听感的问题。

#### 变更

+ `RTCLocalAudioFrameEvent` 改为跟随 Engine 级物理麦克风采集，在 SDK 音频分发线程串行回调，不再依赖某个频道是否发布音频；应用回调耗时不会阻塞上行，旁路队列满载时会丢弃较旧的应用回调帧。

### [2.0.27_screenCapture.1] - 2026.08.25

#### 新增

+ FY 和 WS 流媒体引擎新增 Android 原生屏幕采集能力，支持应用退至后台后继续共享，并支持将同一次屏幕采集发布到多个频道；
+ 新增 Engine 级本地屏幕 I420 帧回调，仅在应用注册监听器后复制并回调帧数据。

#### 变更

+ `LocalScreenTrack.startCapture` 统一为带操作结果回调的启动入口；结果回调表示 SDK 是否接纳启动操作，后续采集状态通过 `RTCScreenStateEvent.onScreenCaptureStateChanged` 通知；
+ 屏幕采集状态类型调整为 `ScreenCaptureState`，包含 `START`、`STOP` 和 `ERROR` 三种状态；
+ FY 和 WS 屏幕采集不再依赖 WebRTC `ScreenCapturerAndroid`，OOK 屏幕采集链路保持不变。

#### 修复

+ 修复共享静态页面时首帧可能长时间不显示的问题；
+ 完善系统停止共享、应用主动停止、屏幕旋转、锁屏以及单应用内容隐藏等场景下的状态通知和资源释放。

### [2.0.28] - 2026.08.22

#### 修复

+ 修复 OOK 媒体客户端释放线程与初始化线程不一致可能导致的不稳定问题。

#### 变更

+ 更新 `librtc.so`，适配服务端移除 OOK 流媒体配置。

### [2.0.27] - 2026.08.19

#### 变更

+ 将 `disconnect-reconnect` 分支合并至 `master`，正式版整合 `2.0.26_disconnectReconnect.1` 的断网重连相关变更。

### [2.0.26_disconnectReconnect.1] - 2026.08.18

#### 修复

+ 修复多频道场景反复断网重连时 WebRTC 资源释放不完整，可能导致应用崩溃的问题。

#### 优化

+ 流媒体断线重连改为 1、2、4、8、16 秒递增等待，之后每 16 秒继续重试；网络恢复后仍会自动重连，降低多频道断网期间的请求压力。

### [2.0.26] - 2026.08.12

#### 新增

+ 支持一个 `RTCEngine` 同时加入多个频道；`join(...)` 返回独立的 `RTCChannel` 句柄，默认频道继续兼容 Engine 扁平接口；
+ 麦克风采集与入会、发布解耦，`LocalMicTrack` 新增显式 `startCapture` / `stopCapture`、输入设备枚举与切换能力；
+ 新增 Engine 全局错误、摄像头设备、麦克风设备和本地 PCM 帧监听器；
+ 新增按公共、频道、摄像头、麦克风、流媒体和 HTTP 分域的 `102xxx` SDK 错误码及 `RtcErrorCatalog` 查询能力。

#### 变更

+ `RTCEngine.create(...)` 新增必填 `RTCEngineEvent`；
+ `RTCEngine.join(...)` 改为接收本频道 `RTCClientEvent` 并返回 `RTCChannel?`，入会结果由 `onJoinSucceed` / `onJoinFailed` 通知；
+ `RTCClientEvent` 的自定义消息、断开和重连回调新增 `channel` 参数，原 `onError(...)` 移至 `RTCEngineEvent`；
+ `RTCMediaEvent` 的所有回调新增 `channel` 参数，摄像头设备事件迁移到 `RTCCameraDeviceEvent`；
+ `RTCRemoteVideoEvent.onReceiveStreamStatusChange(...)` 新增 `channel` 参数；
+ `RTCResultListener2<T>` 更名为 `RTCValueResultListener<T>`，`StatusCode` 与 Android SDK 自产错误码职责分离。

#### 修复

+ 修复多频道场景关闭摄像头后本地采集未停止的问题；
+ 修复断线重连后本地音频静音状态丢失，以及同一轨道重复发布时回调过早失败或丢失的问题。

### [2.0.24_multiChannel.3] - 2026.08.11

#### 修复

+ 修复断线重连后本地音频静音状态丢失的问题，新建音频轨道会继续遵循重连前的启停状态；
+ 修复同一轨道重复发布时后续请求回调过早失败或丢失的问题，合并请求会在真实发布完成后统一返回结果。

### [2.0.25] - 2026.08.11

### [2.0.23] - 2026.07.27
#### 优化
+ 引入远端音频订阅声明式对账器 `SubscribeReconciler`，将同一轨道的订阅和退订操作串行化，避免高频会控事件导致状态不一致；
