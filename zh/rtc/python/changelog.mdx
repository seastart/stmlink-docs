### [0.2.0] - 2026.09.30
本版统一了各端 SDK 的错误码，属于**破坏性变更**。内置 C 库升级到 0.1.0。

#### 破坏性变更
+ **错误码全面重排**：`SdkError.code` 中 SDK 自身的错误码改为「`180` + 3 位跨端统一码」，同一类错误在所有 SRTC SDK 上后三位相同，见 [错误码](/zh/rtc/python/error-codes)。以前落在 `180000`（一般错误）或 `-1`（无错误码）的失败，现在都有了具体的码。**代码里按错误码做判断的，请按下表修改**：

| 场景 | 旧码 | 新码 |
| --- | --- | --- |
| 参数错误（Python 层校验） | `180900` | `180031` |
| 创建本地音频轨道失败 | `-1` | `180025` |
| 无权发布合成流（非 `__mcu__` 身份） | `180004` | `180040` |
| Token 不合法（解析失败、缺字段） | `-1` | `180004` |
| 网络请求失败、HTTP 非 200 | `-1` | `180006` |
| 入会超时 | `-1` | `180007` |
| 服务端响应无法解析 / 缺 `code` 字段 | `-1`（缺 `code` 时当作成功） | `180011` |
| 信令连接失败 / 信令订阅失败 | `180000` | `180009` / `180010` |
| 参数非法（轨道类型不符等，C 库校验） | `180000` | `180031` |
| 频道正在重连 / 流媒体引擎未连接 | `180000` | `180014`（稍后重试即可） |
| 已离开频道后调用会中接口 | `180000` | `180001` |
| 调用顺序不对（引擎未初始化、轨道未就绪等） | `180000` | `180024` |
| 超过发布上限 / 超过订阅上限 | `180000` | `180020` / `180034` |
| 频道内没有该用户 | `180000` | `180204` |
| 该用户没有指定 track_id 的轨道 | `180000` | `180003` |
| 当前引擎不支持该能力（如 `switch_layer`） | `180000` | `180032` |
| 发布 / 订阅被服务端拒绝（如 `1033` 并发已达上限、`1035` 节点满载） | `180300` / `180301` | 服务端原码（`1033` / `1035` 等）原样抛出 |

+ **错误原因改为英文**：SDK 自身抛出的 `SdkError.msg` 以及 `ImportError` / `RuntimeError` 等异常的文案改为英文。请按 `code` / `base_code` 判断，不要按文案判断

#### 新增
+ `srtc.set_language(lang)`：设置语言（如 `"en"`、`"zh-CN"`），进程级生效，随时可调。它决定服务端业务错误（`code` ≥1000）`msg` 的语言；SDK 自身报错始终是英文。不调用或传 `None` / 空串时跟随系统语言（环境变量 `LC_ALL` → `LC_MESSAGES` → `LANG`），系统语言为 `C` / `POSIX` 或都未设置时，服务端按中文返回，与旧版一致
+ `srtc.ErrorCode`：各端统一的 3 位错误码枚举（如 `ErrorCode.INVALID_ARGUMENT` = 31）
+ `SdkError.base_code`：取 SDK 错误码的后三位，用于和 `ErrorCode` 比较；服务端错误码返回自身

#### 修复
+ **短暂断网时直接退出频道**：网络请求失败被误当作服务端拒绝，心跳 / 重连不再重试就退出了频道。现在网络错误会继续重试，只有服务端明确拒绝才退出

### [0.1.1] - 2026.09.26
#### 变更
+ PyPI 项目页改为中英双语说明
+ 安装说明补充：glibc 低于 2.28 的 Linux（如 CentOS 7）需固定依赖版本 `pip install srtc "av>=12,<14"`

<Note>
接口与行为无变化，0.1.0 可直接升级。
</Note>

### [0.1.0] - 2026.09.26
首个版本，发布到 PyPI：`pip install srtc`。

#### 新增
+ 加入 / 离开频道，成员、轨道、频道信息查询，自动订阅与手动订阅
+ 远端音频解码为指定格式的 PCM，按 RTP 时间戳补齐 DTX 静音帧，时间轴连续
+ 发布音频：任意采样率 PCM 写入，SDK 重采样、编码并按实时节奏发送；`clear()` 支持插话打断，`write()` 自带背压
+ 远端视频接收，可选解码为 RGB 图像，解码出错自动请求关键帧
+ 说话人、网络质量、切层、自定义消息事件，断线原因区分被踢 / 顶号 / 频道销毁
+ `async for` 逐帧消费与 `ChannelHandler` 回调两种用法
+ 内置 pipecat transport（`pip install "srtc[pipecat]"`）
+ 平台：Linux x86_64 / aarch64、macOS Apple Silicon、Windows x64，Python 3.10+

<Note>
本版只支持接收视频，不支持发布视频。
</Note>
