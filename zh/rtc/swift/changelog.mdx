### [1.5.3] - 2026.10.10
#### 新增
+ **频道级 MCU 合成视频订阅**：`Channel.subscribeRemoteVideoMcuTrack()` / `unsubscribeRemoteVideoMcuTrack()` / `remoteVideoMcuTrack` 与 `RemoteVideoMcuTrack`。服务端合成任务以保留身份 `__mcu__` 发布合成流，这个身份**不在频道成员列表里**，`subscribeRemoteVideoTrack(uid:trackId:)` 找不到它；新接口按保留标识直接订阅，重复调用返回同一轨道。收流超时 / 恢复照常经 `didChangeReceiveStreamStatus` 上报，`uid` 为 `"__mcu__"`。网宿 CDN 引擎同样支持（拉 `rtc_v_channel_{频道}` 流）。

<Note>
只新增接口，1.5.2 的接入代码可直接升级。平台下限不变（iOS 16 / macOS 14）。合成任务没开时订阅不会出画面（SDK 重试几秒后放弃，不抛错），任务开始运行后再订一次即可。

`SRTCBroadcastKit` 本次为 **1.0.16**，代码无变化，仅随 SDK 同步递增版本号。
</Note>

### [1.5.2] - 2026.10.10
#### 修复
+ **iOS 通话音频会话被外部改掉后可以自愈**：SDK 占用通话音频会话期间，如果宿主 App 自己把会话类别改成了别的（常见于后台保活、播放提示音时设成 `.playback`），录音链路会当场停掉、状态栏橙色麦克风指示点消失，而且之后再开麦也救不回来，这一场的麦克风一直无声。现在再次开麦或再次入会时，SDK 会检查类别是否被外部顶走，是则重新下发通话配置并拉起录音。
+ **离会后不再上报音频路由变化**：离会时 SDK 把音频会话还给系统，系统随即把输出从听筒切回扬声器，旧版仍会补发一次路由变化回调，宿主据此弹出「已切换为扬声器模式」之类的提示。现在未占用音频通道时不再回调；`.oldDeviceUnavailable`（如拔耳机）后的回落重设照常执行。

<Note>
本版为纯修复，没有公开 API 变动，1.5.1 的接入代码可直接升级。平台下限不变（iOS 16 / macOS 14）。建议宿主 App 在 SDK 占用音频会话期间（`AudioRouteSession.isEngaged` 为 `true`）不要改会话类别，自愈只是兜底。

`SRTCBroadcastKit` 本次为 **1.0.15**，代码无变化，仅随 SDK 同步递增版本号。
</Note>

### [1.5.1] - 2026.10.01
#### 修复
+ **`AudioRoute.displayName` / `AudioRouteTarget.displayName` 按系统语言返回中文或英文**：此前一律返回中文（「扬声器」「听筒」等），英文系统的 App 直接拿来显示就会在英文界面里夹着中文。现在系统首选语言以 `zh` 开头（`zh-Hans` / `zh-Hant` / `zh-HK` 等）时返回中文，其余返回英文（`Speaker`、`Earpiece`、`Bluetooth headset`、`Wired headset`、`Unknown route`）。它是给终端用户看的文案，只跟随**系统语言**，不受 `SRTCEngine.language` 影响。

<Note>
本版为纯修复，没有公开 API 变动，1.5.0 的接入代码可直接升级。英文系统下 `displayName` 的返回值从中文变为英文，若业务代码拿它做字符串比较（而不是按 `AudioRoute` 取值判断），请改为按枚举值判断。平台下限不变（iOS 16 / macOS 14）。

`SRTCBroadcastKit` 本次为 **1.0.14**，代码无变化，仅随 SDK 同步递增版本号。
</Note>

### [1.5.0] - 2026.09.30
<Warning>
**本版是破坏性变更**：错误码按跨端统一码表（第 2 版）全面重排，报错文案改为英文。凡是按 `SRTCError.code` 的数值、或按 `message` / `localizedDescription` 的中文文字做判断的代码，升级后都需要调整；按 `SRTCError` 的 case 做 `switch` 的代码不受数值变化影响，但下表中「改抛了另一个 case」的场景要改分支。版本号只升 minor，按 `from: "1.4.x"` 接入的工程会**自动**解析到本版，升级前请先看完下表。
</Warning>

#### 新增
+ **`SRTCEngine.language`**（`String?`，BCP 47 语言标签，如 `"en"`、`"zh-CN"`；`nil` = 跟随系统语言）与只读的 **`currentLanguage`**（实际生效的语言：已设置取设置值，否则取系统首选语言，取不到为 `"zh"`）。SDK 请求后端时带上 `Accept-Language`，**后端返回的业务错误（码 1000–99999）文案随之中 / 英**；SDK 自身的报错一律英文，不受它影响。与 `logLevel` 一样是进程级全局设置，建议在 `joinChannel` / `enableIm` 之前设置。
+ **`SRTCError.baseCode`**：低 3 位语义码，跨端统一（如 `231` = 无摄像头权限），便于与 Web / Android / 鸿蒙端对照；后端业务码返回自身。
+ **`SRTCError` 实现 `CustomNSError`**：桥接成 `NSError` 后 `domain = "cn.seastart.srtc"`、`code` 为完整码（如 `103231`），ObjC / uni-app / Flutter 等走 `NSError` 的集成方可直接按码判断。
+ 新增错误 case：`cameraPermissionDenied`（231）、`microphonePermissionDenied`（251）、`screenShareDenied(_:underlying:)`（039，`underlying` 为系统原始错误，桥接后放在 `NSUnderlyingErrorKey`）、`invalidArgument`（031）、`userNotFound`（204）、`featureNotSupported`（032）、`cameraFormatUnavailable`（242）、`publishFailed`（300）、`subscribeFailed`（301）。
+ `SRTCBroadcastKit`（本次 **1.0.13**）：结束广播时的系统弹窗文案按系统语言出中文或英文；子类可重写 `SRTCBroadcastSampleHandler.finishMessage(for:)` 自定义文案（参数为新增的结束原因枚举 `SRTCBroadcastFinishReason`），内置中英文案可通过 `builtinFinishMessage(for:language:)` 取用。

#### 变更
+ **报错文案全部改为英文**：`SRTCError.message` / `localizedDescription`（格式仍为 `"<code>: <message>"`）以及拼进报错里的参数说明、`BroadcastError` 描述、`screenBroadcastDidFinish` 的 `reason` 均改为英文。它们是给开发者和日志看的，**给终端用户的提示请按 `code` / `baseCode` 自行映射**，不要直接展示 `message`。
+ **HTTP 状态码不再拼进错误码**：此前 HTTP 非 200 会报成 `103<HTTP 状态>`（如 `103502`），与其它低位码撞号；现在一律报 `apiRequestFailed` → **`103006`**，HTTP 状态只放在关联值 `statusCode` 和描述里。
+ **麦克风无权限开麦会抛错**：此前采集「成功」但发出去的是静音，现在抛 `microphonePermissionDenied`（`103251`）。
+ **心跳遇到 HTTP 非 200 / 网络失败不再离会**：只有后端业务错误（码 1000–99999，如被踢出、会话失效）才离会，网关 502 / 504 之类的临时错误改为继续等待重连。
+ `SRTCUniBridge` 回调的错误码不再出现 `-1`：非 `SRTCError` 的错误归一为 006（网络）/ 026（取消）/ 025（内部错误）。

#### 旧码 → 新码对照

| --- | --- | --- |

<Note>
已有的 `SRTCError` case 一个没删、签名没改（新增 case 二进制兼容），编译层面 1.4.7 的接入代码可直接升级；需要检查的是**按数值 / 中文文案判断错误、以及 `switch` 里依赖上表旧 case 的分支**。平台下限不变（iOS 16 / macOS 14）。

`SRTCBroadcastKit` 本次为 **1.0.13**。做 iOS 全屏屏幕共享的接入方，Broadcast Upload Extension target 链接的也要是本 tag 的 `SRTCBroadcastKit`，否则结束弹窗仍是旧文案。
</Note>

### [1.4.7] - 2026.09.23
#### 修复
+ **未知 `device_type` 不再让整份成员列表解析失败**：后端新增端侧类型的节奏不受 SDK 发版控制，而此前 `channel/detail` 的 `users` 里只要有**一条** `device_type` 超出本版本的枚举，整个响应就解不出来、入会直接失败（报 `The data couldn't be read...`）——等于一个陌生端进会就能把所有老版本客户端挡在门外。现在 `DeviceType` 补齐了 `unknown` 与 80–89 服务端代理号段（MCU/SIP/H.323/GB28181/RTSP/RTMP/文件播放/流分发/语音转写），`users` 改为逐条解析、跳过解不出的那条。
+ **SFU 逐条拒绝的订阅不再静默失败**：`sfu/subscribe` 对单条轨道的拒绝是放在 HTTP 200 + `code:0` 的响应体里（`failed` 字段）而不是抛错，因此外层重试一次都不会触发，而调用侧的 `subscribe()` 早已返回成功。这一路订阅之后再也救不回来：内部登记还挂着会短路重订，收流超时又是边沿事件、从没建立起来的订阅不产生边沿，表现为**远端画面永久停在最后一帧或黑屏**。现在按轨道指数退避重投 5 次（约 6 秒），用尽后撤销内部订阅登记，把重订的权利交还业务层。

#### 变更
+ `UserInfo.deviceType` 语义调整：`nil` 现在表示「本 SDK 不认识这个端」，不再只是「对端没上报」。按端型分支的业务代码请把 `nil` 当作未知端处理，不要当成缺省端型。

<Note>
本版为纯修复，没有公开 API 变动，没有破坏性变更，1.4.6 的接入代码可直接升级。平台下限不变（iOS 16 / macOS 14）。

`SRTCBroadcastKit` 本次为 **1.0.12**，代码无变化，仅随 SDK 同步递增版本号。
</Note>

<Warning>
第二条修复只是把「静默失败」变成「重试后可感知、可重订」，**并不解决 SFU 侧拒绝订阅的根因**。若服务端持续返回 `not found`，重试用尽后该路订阅仍会失败，此时属于服务端问题，请从服务端排查。
</Warning>

### [1.4.6] - 2026.09.23
#### 修复
+ **摄像头采集方向跟随界面方向，设备平放不再回落竖屏**：此前设备平放在桌面上（`faceUp` / `faceDown`）或方向未知时，一律按竖屏处理，于是**锁定横屏的 App 里，把设备放到桌上就会突然推出一路竖画面**，对端只能在横向窗口里看到上下加黑边的画面——即业务侧反馈的「横竖屏采集画面自己切来切去」。现在优先按 `UIWindowScene.interfaceOrientation` 解析（宿主锁横屏时它恒为横向），取不到才退回设备方向；平放与未知方向维持上一次有效方向，不再回落竖屏。
+ **横屏屏幕共享画面倒 180°**：ReplayKit 在 `RPVideoSampleOrientationKey` 里给的是 `CGImagePropertyOrientation`（描述「这一帧怎么摆才是正的」），而 SDK 内部的 `VideoRotation` 描述的是「接收端要顺时针转多少度」，两者方向相反。此前把 `right` / `left` 当作同向直接映射，导致**两种横屏都差 180°**，表现为老师横屏发起屏幕共享、学生看到的画面是倒的。现已修正映射关系。

<Note>
本版为纯修复，没有公开 API 变动，1.4.5 的接入代码可直接升级。

第二条修复落在 `SRTCBroadcastKit` 里，本次版本为 **1.0.11**。做 iOS 全屏屏幕共享的接入方升级后，请确认 Broadcast Upload Extension target 链接的是本 tag 的 `SRTCBroadcastKit`（它与本包同 tag 发布，不需要也不应该单独指定版本）——扩展侧若仍是旧包，方向映射不变，共享画面依旧是倒的。
</Note>

### [1.4.5] - 2026.09.18
#### 新增
+ **远端视频收流超时 / 恢复检测**：新增 `ChannelDelegate` 的 `channel(_:didChangeReceiveStreamStatus:)` 回调与 `ReceiveStreamStatus`（`uid` / `trackId` / `trackDesc` / `timedOut`），另有 `RemoteVideoTrack.isReceiveTimedOut` 可随时查询。**按轨道判定**：订阅之后连续一段时间没收到该路视频帧即判超时，帧一恢复立即再报一次，用来驱动画面上的「加载中 / 对方网络异常」指示。订阅后首帧到达时会先收到一次 `timedOut == false`，据此关掉初始 loading。对应老 `RTCEngineKit` 的 `engineChannel:onReceiveStreamStatusChange:trackId:status:`，`timedOut` 与老版 `status` 真假值一致（`true` 为超时），迁移不需要取反。
+ **音频单元启停**：新增 `AudioRouteSession.setAudioModuleEnabled(_:)` 与 `isAudioModuleEnabled`（iOS）。录像直播课这类**纯本地播放**场景可以停掉 VoIP 语音处理单元，避免它压低 `AVPlayer` 的播放音量。

<Warning>
`setAudioModuleEnabled(false)` 期间**通话音频收不到也发不出**，本地播放结束后必须调回 `true`，否则这一场后面全程是哑的。唯一不用自己收尾的情况是重新入会：每次**首次**占用音频通道（入会 / 开始采集）会自动复位为 `true`，上一场的手动停用状态不会跨会话泄漏，与老版 `RTCEngineKit` 进房即 `enabledAudioModule:YES` 一致。
</Warning>

<Note>
不要用 `didChangeConnectionQuality` 代替收流超时检测。质量档位描述的是整条链路「网好不好」，不是「这一路画面停没停」：单路轨道被停推、发送端摄像头卡死、某一路解码失败时，链路档位可以一直是 excellent；反过来网络抖一下档位掉了，几路画面其实都在正常出帧。

本版为纯新增公开 API，协议方法带默认空实现，无破坏性变更，1.4.4 的接入代码可直接升级。`SRTCBroadcastKit` 本次为 **1.0.10**，代码无变化，仅随 SDK 同步递增版本号。
</Note>

### [1.4.4] - 2026.09.15
#### 变更
+ 网宿(CDN) 视图录制共享视频流现在与标准屏幕共享一样附带麦克风录制音频；SRTCBroadcastKit 升级至 1.0.9。
+ 保持音频录制链路预热，避免播放音量降低：音频设备初始化和播放路径切换时不再意外中断录制链路。

### [1.4.3] - 2026.09.14
#### 新增
+ **网宿(CDN) 频道的屏幕共享流自带音频，云端录制不再是哑的**：网宿的云端录制按流名整条流拉取，此前屏幕共享流里只有视频，录出来的共享片段没有声音。现在发布屏幕共享时会在同一条推流连接上追加一路 opus 音频（封顶 32kbps），业务代码无需改动。这路音频**只有 CDN 录制看得见**——它不上报信令、订阅侧也协商不出来，所以远端不会多出一个音频轨道，订阅逻辑与回调完全不受影响。

<Note>
这路音频取自与麦克风相同的本地混音输出，**没有单独的开关**：未发布麦克风轨道、或调用`LocalMicTrack.mute()`时，硬件麦克风在音频设备模块层面就是静音的，混出来的数据里没有人声，录制音频里同样没有——「没开麦就不会被录进去」。macOS 上只共享屏幕音频时，录进去的就只有屏幕声音。

仅网宿(CDN) 引擎；SeaStart(SFU) 频道的录制由服务端按轨道混流，不受本次改动影响。
</Note>

#### 修复
+ **取消发布音频失败后，对端显示麦克风已开却听不到声音**：关闭麦克风时 SDK 要取消发布内部的混音音频轨道，这一步会走一次 HTTP 请求，网络抖动就可能失败（实测`NSURLError -1005`）。此前 SDK 在请求发出前就把轨道句柄置空了，失败时不回滚——服务端那条轨道其实还在，于是下次开麦会**另起一条**音频轨道，对端订阅到的往往是那条早已没人喂数据的旧流。现在只有取消发布成功才释放句柄，失败可自愈：下次开麦会正确复用已有的那条轨道，不会产生第二条。

<Note>
`SRTCBroadcastKit`本次为 **1.0.8**，代码无变化，仅随 SDK 同步递增版本号。
</Note>

### [1.4.2] - 2026.09.12
#### 新增
+ **macOS 整屏共享支持按窗口排除**：`createLocalScreenTrack(source:preset:audioPreset:)`新增`excludedWindowIds`与`excludesCurrentApplication`两个带默认值的参数，`ScreenCaptureOptions`同步新增同名属性。`excludedWindowIds`的取值是`UInt32(NSWindow.windowNumber)`，仅在共享**整个显示器**时有意义（采集单个窗口时忽略）；列表在`startCapture()`时快照一次，之后新开的窗口一律进画面。两个参数都有默认值，现有调用点源码兼容。

#### 变更
+ **macOS 整屏共享默认包含本 App 自己的窗口**：此前 SDK 把整个进程的窗口都从画面里挖掉，表现为「共享整屏时对端看不到你自己的应用窗口」——这不是系统限制，是 SDK 自己排的。现在改为默认包含，与 Zoom / 腾讯会议一致，需要挖掉的窗口通过`excludedWindowIds`逐个指定。
+ `ScreenCaptureSources.availableWindows(includeCurrentApp:)`的默认值由`false`改为`true`，自己的窗口可以作为单窗口共享源出现在列表里。

<Warning>
放开自身窗口后，**任何正在渲染这路共享画面的窗口都会形成无限镜像**（界面上的共享预览窗口，或同机双开自测时渲染远端共享流的会中窗口）。把这些窗口的 ID 放进`excludedWindowIds`逐个挖掉，不要为此把整个 App 排除掉；确实要回到旧行为，把`excludesCurrentApplication`置`true`（此时`excludedWindowIds`被忽略）。
</Warning>

#### 修复
+ **只共享屏幕音频时麦克风被一起发出去**：mix 模式下所有音频源共用同一条采集流，原先靠混音节点的音量决定要不要混入麦克风，但那个节点实际上没有输入，改它的音量对硬件麦克风毫无作用——结果是业务侧没有发布麦克风轨、只共享屏幕音频时，对端仍能听到本端的环境声。现改为在音频设备模块层面直接静音硬件麦克风（默认静音，只有发布麦克风轨或`LocalMicTrack.unmute()`才解除），屏幕音频与自定义音频注入的声音不受影响。
+ 同一根因下，macOS 上`LocalMicTrack.mute()`此前是空操作（调用后对端仍能听到），现已真正生效。

<Note>
`SRTCBroadcastKit`本次为 **1.0.7**，代码无变化，仅随 SDK 同步递增版本号。
</Note>

### [1.4.1] - 2026.09.11
#### 修复
+ **网宿(CDN) 频道下`ChannelDelegate.didChangeActiveSpeakers`不再触发**：活跃说话人此前只有 SeaStart(SFU) 引擎有数据（由服务端通过信令通道下发），CDN 链路上没有该通道，导致同一个对外回调在 网宿频道里恒不触发，业务据此绘制的音量条、发言人提示会静默失效且无任何报错。现在 CDN 侧在本地按 WebRTC 标准统计（`inbound-rtp`的`audioLevel`）每 500ms 采样一次，产出与 SFU 完全相同的`ActiveSpeakersSnapshot`，两种引擎对外行为一致，业务代码无需改动。

<Note>
CDN 架构下没有服务端控制面，说话人只能由本地统计推导，因此与 SeaStart 相比有两点固有差异：只能反映**已订阅**的音频流（未订阅的成员检测不到）；精度与实时性略低于服务端判定。SeaStart 仍走服务端下发那条路，不受本次改动影响。

`ActiveSpeakersSnapshot`只包含**远端**说话人、不含自己，两种引擎一致。需要本端音量请用`SRTCEngine.audioCaptureProcessor`从采集 PCM 自行计算。

`SRTCBroadcastKit`本次为 **1.0.6**，代码无变化，仅随 SDK 同步递增版本号。
</Note>

### [1.4.0] - 2026.09.09
#### 新增
+ **虚拟背景**：在摄像头采集链路上做人像分割，把人像之外的区域替换成虚化或指定图片，装载不需要授权密钥。`SRTCEngine`新增`installVirtualBackground(modelPath:)`、`uninstallVirtualBackground()`、`enableVirtualBackground(_:)`、`isVirtualBackgroundEnabled`、`setVirtualBackgroundBlur(level:)`、`setVirtualBackgroundImage(_:)`、`setVirtualBackgroundInferenceInterval(_:)`、`setVirtualBackgroundMaskSync(_:)`，以及实例访问器`virtualBackground`（诊断用只读状态与`droppedFrameCount`）。配套新增类型`SRTCVirtualBackground`、`SRTCVirtualBackgroundEffect`、`SRTCNativeImage`，详见[虚拟背景](/zh/rtc/swift/advanced/virtual-background)；
    - 开启后**自动作用于所有摄像头轨道**（含开启之后才新建的），不需要往`videoProcessors`里挂东西；
    - 状态整机一份，切前后摄像头 / 切换摄像头设备后不需要重新下发配置；
    - 分割失败或输出缓冲池耗尽时**丢掉该帧**而不是送出未处理的原始画面（避免把真实背景闪给对端），丢帧计数见`virtualBackground.droppedFrameCount`。
+ `SRTCEngine`新增`defaultVideoProcessors`：视频处理器管线配置一次，此后新建的摄像头轨道自动带上（摄像头轨道每次开摄像头都是新建的，只在轨道上设一次会丢）。
+ `SRTCError`新增四个取值：`virtualBackgroundAlreadyInstalled`、`virtualBackgroundNotInstalled`、`virtualBackgroundModelNotFound(String)`、`virtualBackgroundSessionFailed(String)`。

<Warning>
**最低系统要求抬到 iOS 16.0 / macOS 14.0**（此前为 iOS 13.0 / macOS 10.15）。这是破坏性变更：低于此下限的工程解析不到本版本及以后的版本，报的是依赖解析失败而不是编译错误。下限由虚拟背景的推理运行时决定，SwiftPM 的`platforms:`是包级的、没有 target 级下限，无法只让虚拟背景吃这条线。
</Warning>

<Note>
`SRTCError`是非 frozen 的公开枚举，若你对它写了穷举`switch`，需补`@unknown default`分支才能编过。

`SRTCBroadcastKit`本次为 **1.0.5**，代码无变化，仅随 SDK 同步递增版本号。它**不含** `onnxruntime`（Broadcast Upload Extension 进程有 50MB 内存上限）。
</Note>

### [1.3.0] - 2026.08.20
#### 新增
+ **iOS 音频路由**：新增`AudioRouteSession.shared`，统一管理 iOS 的音频会话与输出路由。配套新增类型`AudioRoute`（当前路由，只读五态，含蓝牙 / 有线耳机）、`AudioRouteTarget`（可切换目标，扬声器 / 听筒两态）、`AudioRouteInfo`、`AudioCallState`，以及事件协议`AudioRouteSessionDelegate`（路由变化 / 会话中断 / 中断恢复 / 系统通话状态）。
    - **持久设置**`defaultAudioRoute`：入会前设定默认走扬声器还是听筒，长期有效，外设拔出后按它回落；
    - **临时设置**`setAudioRoute(_:)` / `clearAudioRouteOverride()`：通话中临时切换，优先级高于持久设置；
    - 外接设备（蓝牙 / 有线）由系统接管，SDK 只上报不主动切换 —— iOS 无可靠手段指定具体外设，需要用户主动选择时请用系统的`AVRoutePickerView`。
+ `DeviceManager`新增`isSpeakerOutputPreferred`，用于查询当前是否走扬声器外放。

#### 变更
+ **iOS 加入频道时即建立通话音频通道并保持到离会**，「开不开麦」只决定是否推流，不再影响底层音频采集是否运行。这是让不开麦时也能切换听筒 / 扬声器的前提。
+ `DeviceManager.setSpeakerOutputPreferred(_:)`语义对齐主流 RTC SDK：`true`切扬声器、`false`切听筒（此前`false`表示「撤销覆盖、回到系统默认」，结果不确定）。方法签名未变，调用方无需改动。

<Warning>
**iOS 加入频道时会申请麦克风权限**，即使用户只打算旁听。请确认`Info.plist`含`NSMicrophoneUsageDescription`，否则应用会崩溃。

**加入频道期间 iOS 状态栏会显示橙色麦克风指示点**，这是`.playAndRecord`会话类别的固有表现（与 Zoom、腾讯会议等一致），并非 SDK 额外录音。

若用户拒绝麦克风权限，SDK 会降级为仅播放：仍可听到对方，但听筒路由不可用。
</Warning>

<Note>
`SRTCBroadcastKit`本次为 **1.0.1**，代码无变化，仅随 SDK 同步递增版本号。
</Note>

</Warning>

#### 新增
+ **iOS 全屏屏幕共享**：`createLocalScreenTrack(mode:)`新增采集方式参数，`.broadcast(appGroup:)`基于 ReplayKit Broadcast Upload Extension 采集整个系统屏幕；原有的应用内采集为默认值`.inApp`，行为不变。配套新增：
