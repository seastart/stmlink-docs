设备接入解决的是「不跑我们 SDK 的东西也要进会」：会议室里的 SIP 话机、墙上的国标摄像头、
一路 RTSP 流。它们由**设备网关**代理入会，在频道里表现为一个普通成员（`uid` 带 `_agent_` 前缀）。

单个接口的参数与返回结构见[设备接入](/zh/rtc/server-api/agent)。

不写代码、只想在管理后台和设备上完成配置（终端怎么注册、拨什么号、国标摄像头怎么填），看[设备接入使用说明](/zh/product/device-access/overview)。

## 三步接入

```text
1. 拿网关            POST /server/v1/agent/list-gw?type=regsip   → gw
2. 登记设备          POST /server/v1/agent/create?type=regsip    → 设备 ID
3. 拉进频道          POST /server/v1/agent/invite                → 等 user_join 回调
```

设备不是直连 RTC，而是挂在某个网关上，由网关负责信令与媒体转换。所以**第 1 步不能跳过**——
`gw` 填错会导致设备无法上线。

## 六种接入方式

`type` 是 **URL 查询参数**（`?type=regsip`），不在请求体里。[新增设备](/zh/rtc/server-api/agent#新增设备)与
[修改设备](/zh/rtc/server-api/agent#修改设备)的请求体字段随它变化：

| `type` | 说明 | 特有必填字段 |
| --- | --- | --- |
| `ipsip` | SIP 话机，IP 直连 | `uri`（`ip:port`）|
| `regsip` | SIP 话机，注册模式 | `username`（不能含 `:`）、`auth_pwd` |
| `iph323` | H323 终端，IP 直连 | `uri`（`ip:port`）|
| `regh323` | H323 终端，注册模式 | `username`（**只能是数字短号**）、`auth_pwd` |
| `gb28181` | 国标监控设备 | `sip_no`（18–20 位数字）、`auth_pwd`，可选 `subjects` |
| `rtsp` | RTSP 拉流 | `uri`（必须以 `rtsp` 开头），可选 `transport_type`（`UDP` 默认 / `TCP`）|

上表只列各方式**特有**的字段，每种取值下的完整请求体见
[新增设备](/zh/rtc/server-api/agent#新增设备)（按 `type` 分节列出）。
所有方式都必填 `display_name`（显示名称）和 `gw`（设备网关），`remark` 可选。
`rtsp` 之外的方式还需要注意：注册模式要求设备主动向网关注册，IP 直连则由我们去连设备，
选哪种取决于设备所在网络能不能被我们访问到。
注册模式与 IP 直连的设备上线、离线都可以订阅 `agent_online` / `agent_offline` 回调来感知（IP 直连设备的在线状态由设备网关定时探测得出），见[回调事件接入指南](/zh/rtc/server-api/guides/callbacks)。

修改设备时 `type` **必须与设备登记时一致**，不能借此把 SIP 设备改成 RTSP；
要换接入方式请删除后重新登记。

## 国标设备的通道

一台国标设备（NVR、球机）下面可能挂多个摄像头通道，每个通道在会中是一路独立画面。
`subjects` 是「通道编号 → 通道名称」的键值对：

```json
{"50010700001320000001": "嘉宾席", "50010700001320000002": "观众席"}
```

三种维护方式，效果相同：

+ 登记设备时用 `subjects` 一次性批量传入
+ 之后用[设置国标设备的一个通道](/zh/rtc/server-api/agent#设置国标设备的一个通道)逐个添加或改名
+ 编号懒得自己拼 → 先调[生成国标设备的通道编号](/zh/rtc/server-api/agent#生成国标设备的通道编号)按规范生成，再登记

同理，设备本身的 `sip_no` 也可以用[生成国标设备的 SIP 编号](/zh/rtc/server-api/agent#生成国标设备的-sip-编号)拿到。
两个"生成"接口都**只返回编号、不落库**，拿到后还得自己去登记。

要让国标摄像头能注册上来，设备端得填"上级平台"信息（SIP 编号、域、IP、端口）——
这些值从[设备网关平台信息列表](/zh/rtc/server-api/agent#设备网关平台信息列表)取。

## 邀请与会中操作

[邀请设备入会](/zh/rtc/server-api/agent#邀请设备入会)的 `agents[].type` 与 `contact` 从
[设备列表](/zh/rtc/server-api/agent#设备列表)取；国标设备的每个通道各占一条，`contact` 就是通道编号。

**入会是异步的**：接口返回成功只表示邀请已下发，设备真正上线要等 `user_join` 回调。
如果你订阅了 `agent_join` 回调，还必须在回调里返回 `sid`，否则设备进不来——见[回调事件接入指南](/zh/rtc/server-api/guides/callbacks)。

设备不能自己开关麦克风和摄像头，只能由服务端下发：
[开关设备视频](/zh/rtc/server-api/agent#开关设备视频) / [开关设备音频](/zh/rtc/server-api/agent#开关设备音频)；
会议声音要不要从设备喇叭放出来，用[开关设备喇叭](/zh/rtc/server-api/agent#开关设备喇叭)（见下文「设备喇叭」）。
`uid` 用设备在频道里的用户 ID（带 `_agent_` 前缀，从成员列表或 `user_join` 回调拿），
不传 `uid` 则对该频道内所有设备生效。

订阅了 `agent_operate` 回调时，这两个操作会先征询你的业务后端，返回非 0 即拒绝。

### 邀请时的初始开关

[邀请设备入会](/zh/rtc/server-api/agent#邀请设备入会)时，`agents[]` 每项可以带四个可选开关，决定设备入会后先发什么、放不放会议声音：

| 参数 | 默认 | 含义 |
| --- | --- | --- |
| `camera_enabled` | `true` | 入会后是否发摄像头画面 |
| `mic_enabled` | `true` | 入会后设备麦克风的声音是否进会（上行） |
| `share_enabled` | `false` | 入会后是否直接共享画面 |
| `speaker_enabled` | SIP/H.323 `true`；国标取设备网关配置（默认 `false`） | 会议声音是否从设备喇叭放出来（下行），RTSP 等拉流设备忽略 |

+ `mic_enabled` 与 `speaker_enabled` 成对：前者管「设备说的话会里听不听得到」，后者管「会里说的话设备那头听不听得到」
+ 前三个开关只是「想要开着」，**仍受会议禁止策略约束**：会议禁了摄像头，传 `camera_enabled: true` 也开不了（经 `agent_operate` 回调被你的业务后端拒绝）
+ `share_enabled` 只对 RTSP / 国标等**拉流设备**生效：入会后先经 `agent_operate`（`agent_start_share`）申请共享，放行则主画面以屏幕共享发布；**被拒则退回作为普通摄像头画面**发布（`camera_enabled` 为 `false` 时不发视频）
+ SIP/H.323 设备**不支持** `share_enabled: true`：只要有一台这样传，整个邀请返回错误码 `1037`，一台都不呼。终端要共享请在终端上按共享键（见下节）

### 设备共享

设备的共享在频道里以屏幕共享（`screen`）发布，客户端和 MCU 合成画面都把它当普通屏幕共享处理。两类设备的语义不同：

+ **RTSP / 国标等拉流设备**（只有一路画面）：共享就是把主画面**切成**屏幕共享发布，摄像头画面随之撤下；停止共享切回摄像头画面
+ **SIP/H.323 终端**：**不支持由平台远程开启共享**，只能由终端在本地按共享键发起：辅流以屏幕共享发布，摄像头画面照旧

共享有两种发起方式：

+ **终端本地按共享键**（仅 SIP/H.323）：先经 `agent_operate` 回调（`op_type` 为 `agent_start_share`）征询你的业务后端，返回非 0 即拒绝，终端会收到拒绝应答；终端停止共享时回调 `agent_stop_share`。见[回调事件接入指南](/zh/rtc/server-api/guides/callbacks)
+ **由服务端指定**：[开关设备共享](/zh/rtc/server-api/agent#开关设备共享)，`enabled` 传 `true` 开始、`false` 停止。`true` 仅对拉流设备有效，对 SIP/H.323 终端传 `true` 返回错误码 `1037`；`false` 对两类设备都可用，SIP/H.323 终端自己按键发起的辅流会被撤销。这个接口**不做共享互斥**，频道里同一时刻只允许一人共享的话，请在业务后端先判断再调用

### 设备喇叭

`speaker_enabled` 决定会议声音（频道混音）是否送到设备、从设备的喇叭放出来。各类设备的效果：

| 设备 | 不传时 | 开（`true`） | 关（`false`） |
| --- | --- | --- | --- |
| SIP/H.323 终端 | `true`（终端一直能听到会议声音） | 把会议声音送给终端 | 终端听不到会议声音；网关改送静音帧，媒体连接不断 |
| 国标监控 | 取设备网关配置（默认 `false`） | 网关向设备发起 GB28181 **语音广播**，会议声音从设备喇叭 / 音柱放出 | 结束语音广播 |
| RTSP 等拉流设备 | — | 没有喇叭，邀请时忽略；会中调用返回成功但无效果 | 同左 |

国标语音广播要同时满足：

+ 设备网关已开启语音广播能力（私有化部署时在网关配置里打开）
+ 设备本身支持 GB28181 语音广播，且接了喇叭或音柱
+ 网关只向设备发 G.711A（PCMA）音频

会中开关用[开关设备喇叭](/zh/rtc/server-api/agent#开关设备喇叭)（`uid`、`channel`、`enabled`）。国标的广播是**异步**发起的：
接口返回成功只代表指令已下发，设备拒绝广播（不支持、没接喇叭等）不会反映在接口结果里，只体现在设备网关日志中。

## 设备类型编号

`list-invite` 与 `invite` 用的是数字类型，与 `type` 字符串不是一套：

| 数字 | 含义 | 对应的 `type` |
| --- | --- | --- |
| 2 | SIP | `ipsip` / `regsip` |
| 3 | H323 | `iph323` / `regh323` |
| 4 | GB28181 监控 | `gb28181` |
| 5 | RTSP 拉流 | `rtsp` |

会中成员的 `device_type` 是第三套编号（`80` 起的代理号段）：经设备网关入会的设备按真实类型上报，即 `80` 加上表中的数字（SIP `82`、H323 `83`、GB28181 `84`、RTSP `85`），见[回调事件接入指南](/zh/rtc/server-api/guides/callbacks)。

## 参数命名约定

开关类参数按后缀区分含义：`xxx_disabled` 表示**不允许**（权限 / 策略，如会议禁止开摄像头），`xxx_state` 表示**查询到的当前状态**，`xxx_enabled` 表示**开 / 关**（命令，或邀请时期望的初始值，仍受 `_disabled` 约束）。
