开启了[转写](/zh/product/ai/transcription)的会议，转写结束后由大模型把整场逐字稿整理成一份**会议纪要**，
会议成员在历史会议里就能看到，不用会后再人工整理。

---

## 纪要长什么样

内置的「通用会议」模板输出 Markdown，固定四个部分：

| 章节 | 内容 |
| --- | --- |
| 会议概要 | 三五句话说明会议目的与整体结论 |
| 议题与讨论要点 | 按议题分条，写清各方观点，标注发言人 |
| 结论 / 决议 | 逐条列出达成一致的事项 |
| 待办事项 | 表格：事项、负责人、截止时间；原文没提到的写「未明确」 |

模板要求大模型**只依据逐字稿、不编造**，数字、专有名词、人名保持原样。纪要质量取决于所用的大模型和识别准确度，
重要的会议仍建议会后人工过一遍。

---

## 怎么生成

1. 主持人开启会议转写，会中正常发言
2. 转写结束（主持人关掉「会议转写」，或会议结束）后，平台把这一场的定稿句按 `[分:秒] 发言人：内容` 拼成逐字稿
3. 交给大模型按模板生成纪要；逐字稿很长时（超过约 1.2 万字）先分段摘要再汇总，避免超出模型的上下文长度
4. 生成完成后，还在会中的成员收到「会议纪要已生成」提示；失败时自动重试，仍失败可以手动重新生成

**一场会一份**：纪要按转写**场次**生成。会中关掉转写再打开仍是同一场，结束后按全部转写内容重新生成并**覆盖**原纪要，不会出现好几份。
主持人或后台管理员也可以换一个模板**重新生成**，同样覆盖原来那份。

## 需要配置什么

| 配置 | 在哪 | 说明 |
| --- | --- | --- |
| 大模型 | 管理后台 **AI 能力 → AI 服务与方案** | 登记客户的大模型服务并放进 AI 方案，见 [AI 服务与方案](/zh/product/ai/models)。没配大模型时不会生成纪要 |
| 自动生成纪要 | **AI 能力 → 应用 AI 设置 → 会议纪要** | 打开「自动生成纪要」；不打开时可以在需要时手动生成 |
| 纪要模板 | 同上，选「纪要模板」 | 不选则用默认模板 |

### 纪要模板

在 **AI 能力 → 纪要模板** 里维护。内置三份：**通用会议**（默认）、**评审会**、**周例会**，可以直接修改，也可以新增。

模板就是一段给大模型的提示词，里面用两个占位符：

+ `{{transcript}}`：整场逐字稿（必须有，否则大模型拿不到会议内容）
+ `{{meeting_info}}`：会议信息（频道、起止时间等）

客户有固定的纪要格式时（比如项目例会要单列「风险与求助」），照着内置模板改章节要求即可。

## 谁能看、在哪看

| 在哪看 | 谁能看 |
| --- | --- |
| 网页会议客户端「历史会议」 | 同一应用下登录的用户（与查看录制详情的权限一致）；有「纪要」「转写原文」两个页签 |
| 管理后台 **AI 能力 → 纪要记录** | 有该菜单权限的后台账号；可查看纪要与转写原文，选模板重新生成 |
| 会议 Web SDK | `aiSummary()` 查纪要，`adminAiSummaryGenerate()` 由主持人重新生成，见 [SMeeting Web 接口](/zh/meeting/web/api-reference/SMeeting) |
| 服务端接口 | [获取 / 生成会议纪要](/zh/rtc/server-api/ai)，只能取本应用的数据；业务系统可以据此把纪要推进 OA、项目管理系统 |

<Note>
会议内容属于客户机密：给大模型的提示词和大模型的输出默认**不写进服务日志**；大模型地址由客户提供，平台不内置任何公网模型。
</Note>
