先确认两件最基础的事，很多问题到这里就解决了：

1. **端口放通了吗**：设备和设备网关之间的信令端口、RTP 端口段都要通，见[网络与端口要求](/zh/product/deploy/ports#设备网关)
2. **设备选对网关了吗**：登记设备时选的「设备网关」，要和终端实际注册、或者能访问到的那个网关一致

---

## 终端注册不上

| 检查 | 说明 |
| --- | --- |
| 地址和端口 | 终端上填的是**设备网关地址**，SIP 端口 5060、H.323 网守端口 1719 |
| 用户名格式 | H.323 用户名**只能是数字**（E.164 短号）；SIP 用户名不能含冒号 |
| 用户名、密码 | 终端上的认证用户名、密码与后台账号完全一致 |
| 网关选择 | 后台账号选的「设备网关」就是终端注册的那台 |
| 网络 | 在终端所在网络上 `ping` 设备网关地址；隔着 NAT 时，注册方向是终端 → 网关，网关地址要对终端可达 |

---

## 终端拨号呼不进会议

| 现象 / 检查 | 原因与处理 |
| --- | --- |
| 未注册的终端只拨了会议号 | 未注册终端要拨 `会议号@设备网关地址` |
| 会议号拨对了还是进不去 | 会议要**存在且未结束**；设备呼入固定进部署时指定的那个应用，会议不在这个应用下就找不到 |
| 刚呼出就被拒 | 设备网关开启了来电 IP 白名单，终端 IP 不在名单里 |
| 只用了 SRTC、没有会议层 | 呼入拨的是**频道名**，不是会议号 |

---

## 终端进会了，但看不到会里的画面

终端看到的是 MCU 合成的整场画面，按顺序查：

1. **MCU 部署了吗、在运行吗**：没有 MCU，终端就收不到画面。管理后台 **运维管理 → 媒体网关** 里能看到 MCU 的心跳
2. **RTP 端口段放通了吗**：设备网关的 RTP 端口段（默认 58000-59000/UDP）要对终端整段放通
3. **网关告诉终端的地址对吗**：部署时填的「设备访问网关 IP」会写进呼叫信令，终端按这个地址回送媒体。
   终端隔着 NAT 访问网关时，这里要填 NAT 后的地址，并且端口要做**同端口号**映射
4. **终端收发端口是否分开**：部分终端（常见于法院、政务定制机型）收和发用不同端口，
   会出现「会里能看到终端，终端看不到会里」。需要在设备网关上关闭 RTP 地址学习，请联系我们调整配置

## 会里看不到终端的画面、听不到终端声音

| 检查 | 说明 |
| --- | --- |
| 终端视频编码 | 终端要用 **H.264** 编码（多数终端默认如此）；音频 G.711A |
| 终端的摄像头、麦克风 | 终端本身没有静音、没有关闭视频；主持人是否在会中关了这台终端的音视频 |
| 端口 | 同上，RTP 端口段要放通 |

---

## 国标摄像头接不上

| 现象 / 检查 | 原因与处理 |
| --- | --- |
| 摄像头上注册状态一直「离线」 | 平台信息（SIP 服务器 ID、域、地址、端口 5070）要与后台「平台信息」完全一致；摄像头要能访问到网关的 5070 端口 |
| 设备 id、密码 | 摄像头的「SIP 用户名 / 认证 ID」= 后台「设备 id」；密码两边一致 |
| 注册上了，过一会儿又离线 | 把摄像头的**心跳周期改成 30 秒** |
| 邀请时报「Device is busy」 | 这个提示并不表示设备忙，绝大多数是**摄像头没有注册上来**。先确认后台状态是「在线」再邀请 |
| 设备在线，邀请后没画面 | 邀请的是**通道**：确认通道 id 与摄像头的「视频通道编码 ID」一致；摄像头编码设为 H.264 |

---

## RTSP 流没画面

| 检查 | 说明 |
| --- | --- |
| 地址能不能播 | 先用 VLC 打开同一个地址，播不了就是地址、账号或设备的问题 |
| 网关访问得到吗 | 是设备网关去拉流，网关所在服务器要能访问到摄像头的 554 端口 |
| 传输类型 | UDP 被拦或丢包严重时，在后台改成 **TCP** |
| 码流编码 | H.265 会实时转码，路数多时网关 CPU 可能不够，摄像头改成 H.264 |

---

## 设备入会被拒、提示并发超限

每台入会的设备同时占用**一个用户并发**和**一个设备并发**名额。名额用满后新设备无法入会，
需要扩充授权，或先让不用的设备离会。设备网关本身也需要授权文件，没有导入授权时设备无法正常接入。
