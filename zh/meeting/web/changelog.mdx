### v0.3.9 - 2026-11-25

#### 新增
+ **会议同声传译**：主持人 / 联席主持人用 `startInterp()` / `stopInterp()` 开关同传（转写没开时自动先开），每个成员用 `setMyInterpLang(lang)` 设置「我的语言」，服务端把每句话翻译成在会成员的语言并合成语音。Web SDK 内置同传播放器，自动依次播放我的语言的译音，播放期间把说话人原声压低（音量来自 AI 方案，默认 20%），播完恢复；`setInterpListenOriginal(true)` 切到只听原声，字幕不受影响。用法见 [SMeeting · 同声传译](/zh/meeting/web/api-reference/SMeeting#同声传译)
+ 新增房间事件 `ROOM_INTERP_STATE_CHANGED`（同传开关变化）、`USER_INTERP_LANG_CHANGED`（成员语言变化），见[事件](/zh/meeting/web/events)；断线重连后有变化时自动补发
+ 新增 `isInterpEnabled()`、`getMyInterpLang()`、`getUserInterpLang(uid)`、`getInterpLangs()`、`isInterpListenOriginal()`；`RoomInfo` 新增 `interp_enabled`、`interp_duck_volume`、`interp_langs`、`interp_default_lang`
+ `ASR_TRANSLATION` 新增 `audio_url`（译音地址，同传开启且合成成功时才有）。同传开启时同一句会按在会成员的语言各来一条，显示字幕时请按 `lang` 过滤为我的语言
+ 底层 SRTC 依赖升级到 Web `^0.7.7`

<Warning>
同传开启时每句会下发多条不同 `lang` 的译文，未按 `lang` 过滤的旧版客户端会把它们都当字幕显示。请会议的各端都升级后再开放同传；现场有反向代理时需放行 `/aiapi/interp-audio/` 路径，否则只有字幕、听不到译音。
</Warning>

### v0.3.8 - 2026-11-24

#### 新增
+ **会前网络检测 `networkCheck`**：入会前调用，不需要入会，已登录时不用传参（未登录传会议 token，或 `appId` + `serverUrl`）。五项检测（网络权限、网络连接、MTU、域名解析、服务器连接）由 SRTC 层完成并原样透传，会议层在服务器连接项里多检测一项会议接口是否可达；`onItem` 逐项回调进度，最后返回汇总结果，每项带可直接展示给用户的说明；可用 `cancelNetworkCheck()` 取消。用法见 [SMeeting · 会前网络检测](/zh/meeting/web/api-reference/SMeeting#会前网络检测)，类型见 [会前网络检测相关](/zh/meeting/web/types#会前网络检测相关)
+ 底层 SRTC 依赖升级到 Web `^0.7.6`

### v0.3.7 - 2026-11-24

#### 新增
+ 新增 `getLocalCameraTrack()` / `getLocalScreenTrack()`：取本地摄像头、屏幕共享轨道，与已有的 `getLocalMicTrack()` 配齐
+ 新增 `subscribeRemoteAudioMixTrack()`：取远端混音流（除自己以外所有人的声音），可配合 `createLocalCompositeRecorder()` 做本地录制。混音流会中只有一份，已在播放时返回同一条轨，不会重复订阅
+ 新增房间事件 `ADMIN_REQUEST_OPEN_SHARE`：主持人请求您共享屏幕，同意时以 `byAdmin = true`、`adminUid = data.op_uid` 调用 `requestShare()` 即可

#### 修复
+ `requestShare()` 以 `byAdmin = true` 调用但 `adminUid` 为空时，共享画面已发出、会议的共享状态却没有更新的问题

### v0.3.6 - 2026-11-18

#### 新增
+ **会中字幕与实时翻译**：主持人用 `adminAsrStart(translateLang?)` / `adminAsrStop()` 开关会议转写，`isAsrEnabled()` 查当前状态。开关变化触发房间事件 `ROOM_ASR_STATE_CHANGED`，字幕原文和译文分别通过 `ASR_RESULT`、`ASR_TRANSLATION` 下发；`RoomInfo` 新增 `asr_enabled`
+ **会后纪要**：`aiSummary(meetingId?)` 查询各场转写及纪要（会后也可查），主持人可用 `adminAiSummaryGenerate(sessionId, meetingId?, templateId?)` 重新生成；纪要生成完成或失败时触发 `AI_SUMMARY_READY`
+ **转写原文**：`aiTranscript(meetingId?, sessionId?)` 查询转写原文，按场次组织，每场句子按时间排序

### v0.3.5 - 2026-11-18

#### 新增
+ **只采集预览（设备检测）**：`requestOpenCamera()` / `requestOpenMic()` 新增末尾参数 `publish`，传 `false` 时只采集、只预览，不请求会控、不发布、不发状态事件，会前会中都可用；之后以 `publish: true` 再调一次会转正发布同一条轨，不重新采集。见 [设备检测](/zh/meeting/web/advanced/device-check)
+ `requestOpenMic()` 返回本地麦克风轨道（`LocalMicTrack`），可直接 `getVolume()` 读音量
+ 新增 `isCameraOpened()` / `isMicOpened()`：是否作为会议摄像头 / 麦克风打开，只预览时为 `false`

#### 修复
+ 入会前打开的摄像头、麦克风，入会后再次调用 `requestOpenCamera()` / `requestOpenMic()` 报「已打开」、无法发布到会议的问题，现在会补发布

### v0.3.4 - 2026-11-18

#### 新增
+ **AI 降噪**：新增 `setAudioProcessor()`，可把 `@seastart/srtc-plugin-deepfilternet` 等麦克风音频处理器交给会议层，之后每次开麦自动挂上、关麦和离会时卸下，见 [AI 降噪](/zh/meeting/web/advanced/deepfilternet)
+ 底层 SRTC 依赖升级到 Web `^0.7.3`

### v0.3.3 - 2026-11-12

#### 修复
+ **被踢出、被顶号或会议结束后，再次入会报「已在会议中」（`206006`）**：之前收到 `DISCONNECTED` 后，SDK 内部的会议状态要等业务方调用 `exitRoom()` 才会清掉；不调用的话，同一个 SDK 实例之后再 `enterRoom` 会被直接拒绝，请求不会发到服务端。现在 SDK 在 `DISCONNECTED` 回调返回后自行清理，可以直接重新 `enterRoom`；回调里照旧调用 `exitRoom()` 也不会出错，已有代码无需修改

### v0.3.2 - 2026-11-09

#### 修复
+ **会外消息（IM）的自定义消息收不到回调**：服务端 [`im/send-msg`](/zh/rtc/server-api/im#发送im消息) 发送的消息，`action` 不是 SDK 内置类型时之前会被静默丢弃，`onNotifyImEvent` 不触发。现在统一以新增的 `CommonImEventType.IM_CUSTOM_MSG` 事件透传，`data` 为 `ImCustomMsgEventData`（含 `action`、`content` 及发送者 `uid` / `name` / `sid`），见 [事件参考 · 会外消息事件](/zh/meeting/web/events#会外消息事件)
+ 去掉收到会外消息时多余的控制台打印

### v0.3.1 - 2026-11-04

+ **兼容 webpack 4 等老工具链**：构建产物的语法降到 ES2019；ESM 产物由 `smeeting.mjs` 改名为 `smeeting.esm.js`（`package.json` 的 `module` / `exports` 已同步，正常 `import` 写法不受影响），修复 webpack 4 默认配置引入时报 `Module parse failed`、`Can't import the named export ... from non EcmaScript module` 的问题。接口与运行行为不变
+ 底层 SRTC 升级到 Web 0.7.1，同样降到 ES2019，见 [SRTC Web 更新日志 · v0.7.1](/zh/rtc/web/changelog)

### v0.3.0 - 2026-09-30

<Warning>
**本版是破坏性变更**：会议层错误码重排、SDK 报错文案改为英文，并新增 `language` 参数。凡是按 `code` 的数值（尤其是 `206000`）或按中文报错文案做判断的代码，升级后都需要按下表调整。完整码表见 [错误码](/zh/meeting/web/error-codes) 与 [错误码规则与总表](/zh/meeting/error-codes)。底层 SRTC 同步升级到 Web 0.7.0，它透传上来的 `106xxx` 也已重排，见 [SRTC Web 更新日志 · v0.7.0](/zh/rtc/web/changelog)。
</Warning>

#### 破坏性变更
+ **会议层错误码重排**：按跨端统一码表分配低 3 位码，不再落在 `206000`。请按 `code` 判断，不要按文案判断
+ **报错文案改为英文**：SDK 自身报错的 `message` / `msg` 全部改为英文，只给开发者和日志看；给终端用户的提示请按错误码自行映射（错误码页有「建议给用户的提示」列）
+ 请求会议服务端的网络失败 / HTTP 非 200 统一为 `206007`，HTTP 状态放在 `message` 里；响应无法解析或缺 `code` 字段为 `206356`
+ 采集 / 权限错误原样透传 SRTC 层的码（如 `106231` 无摄像头权限、`106251` 无麦克风权限、`106039` 屏幕共享被拒），打开失败时的清理步骤不再覆盖原始错误
+ `McuTaskStatus` 取值与服务端对齐：新增 `WaitStart = 0`、`WaitEnd = 2`，`Exception` 由 2 改为 3、`Normal` 由 3 改为 4。按成员名比较的代码升级后即可得到正确语义，**直接写数字 2 / 3 判断的代码需自查**

#### 新增
+ 初始化参数 **`language`**（如 `zh-CN`、`en`；不传则跟随 `navigator.language`，取不到为 `zh`），会同时设置底层 SRTC：请求会议服务端和 SRTC 服务端时都带 `Accept-Language`，**服务端业务错误（`1000`–`99999`）的文案随之返回中文或英文**。SDK 自身的报错固定为英文，不受它影响。见 [类型定义](/zh/meeting/web/types)
+ 初始化参数 `autoPlayDialogText`：覆盖自动播放提示框的文案（默认按 `language` 显示中文或英文）
+ 包里导出 `SdkError` 与 `MeetingErrorCode`（会议层低 3 位）。SRTC 包也导出同名的 `SdkError`，两个包同时引入时请起别名

#### 修复
+ `McuRecordDetail` 类型与服务端实际返回对齐：补齐 `began_at` / `total_duration` / `records` 等字段，`mcu_at` / `mcu_dur` 标记为废弃（服务端仍回填，新接入请改用 `began_at` / `total_duration`）

#### 变更
+ 依赖的 SRTC 升级到 `@seastart/srtc-web-sdk` 0.7.0
+ npm 页面说明改为中英双语，许可证改为专有（UNLICENSED）

#### 旧码 → 新码对照

| 场景 | 0.2.0 及以前 | 0.3.0 |
| --- | --- | --- |
| 未登录 / Token 已过期 / 不在会议中 / 无权限（主持人操作） | `206001` / `206002` / `206003` / `206004` | 不变（文案改英文） |
| 房间已禁止打开摄像头 / 麦克风 / 共享 | `206000` | `206004` |
| Token 无法解析 | 原始解析异常 | `206005` |
| 已在会议中，重复进入 | `206000` | `206006` |
| 请求会议服务端网络失败 / HTTP 非 200 | 不带码的 `Error` | `206007` |
| 会议中没有该成员 | `206000` | `206010` |
| 摄像头 / 麦克风 / 共享已开启时重复开启、尚未开启时切换设备等 | `206000` | `206011` |
| 响应无法解析 / 缺 `code` 字段 | 原始解析异常 / 当作服务端错误 | `206356` |
| 采集 / 权限 / 推拉流失败（SRTC 层透传） | SRTC 旧码或浏览器原始异常 | SRTC 新码，如 `106231`、`106251`、`106039`，见 [SRTC Web 更新日志](/zh/rtc/web/changelog) |
| 服务端业务错误（`1000`–`99999`） | 原样透传 | 原样透传，文案随 `language` 返回中文或英文 |
