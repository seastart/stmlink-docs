### [1.3.8] - 2026.09.23
#### 新增
+ **`updateLocalCameraView(_:)`**：在不中断采集的前提下，把本地摄像头预览的渲染器搬到另一个视图上。UIKit 宿主在宫格重建、首屏与视频墙切换这类布局变化里会销毁并重建承载预览的视图，此前只能关掉摄像头再开一次，现在直接搬迁即可。

#### 修复
+ **摄像头已开启时重复调用 `requestOpenCamera(view:)`，新传入的预览视图被忽略**：此前复用已有轨道的分支直接返回，新视图没有被接上，渲染器还挂在已从视图树上摘掉的旧视图，表现为**本端画面黑屏**（对端一切正常）。现在复用分支会把渲染器搬到新传入的视图上。
+ **已在教室里的学生收不到屏幕共享开始事件**：屏幕共享的开始信号是异步汇合的——房间共享状态（`user_start_room_share` 广播、频道属性里的 `share_state` / `share_uid`）与 `screen` 轨道各走各的路径。此前两条路径各自判定，且没有覆盖属性刷新这一路：广播先到时轨道还没登记、轨道先到时房间状态还没刷新，两边都各自放弃，之后属性刷新到了也没有人补判，结果是**已经在教室里的学生完全收不到 `ROOM_SHARE_START`，退出重进反而能看到**（重进走的是另一条已有共享的通知路径）。现改为三路汇合判定，谁最后到齐由谁触发，防重逻辑不变。

#### 变更
+ SRTC 依赖升级到 **1.4.6**（含摄像头方向与横屏屏幕共享画面倒 180° 两项修复，详见音视频 SDK 的[更新日志](/zh/rtc/swift/changelog)）。

<Warning>
做 iOS 全屏共享的工程，扩展 target 那条额外的 `srtc-swift-sdk` 依赖要**同步改为 `exact: "1.4.6"`**，与本包 pin 的版本保持一致，否则依赖解析冲突。横屏共享画面倒 180° 的修复落在 `SRTCBroadcastKit`（本次 **1.0.11**）里，扩展侧不升就不会生效。
</Warning>

<Note>
本版为纯新增 API + 修复，没有破坏性变更，1.3.7 的接入代码可直接升级。
</Note>

### [1.3.7] - 2026.09.18
#### 新增
+ **会议标题变化事件**：新增 `SMeetingDelegate` 的 `meeting(_:roomTitleDidChange:)` 回调、`RoomTitleChangeEventData`（`title` / `previousTitle`）与 `RoomEventType.roomTitleChanged`。主持人改主会议标题、以及小组会议改名（`adminUpdateSubMeetingTitle`）都会触发，对应老 `MeetingKit` 的 `onRoomMeetingTitleChanged:`。
+ **远端视频收流超时 / 恢复**：新增 `meeting(_:didChangeReceiveStreamStatus:)` 回调与 `RoomEventType.receiveStreamStatusChanged`，按轨道判定某一格画面是否停止出帧，用来开关「加载中」指示。载荷直接复用音视频 SDK 的 `ReceiveStreamStatus`，未再包一层会议专属结构。对应老 `MeetingKit` 的 `onReceiveStreamStatusChange:streamType:status:`。
+ **音频单元启停**：新增 `SMeetingEngine.setAudioModuleEnabled(_:)` 与 `isAudioModuleEnabled`（iOS），是音视频 SDK `AudioRouteSession` 同名接口的薄封装，供录像直播课这类纯本地播放场景使用。

#### 变更
+ SRTC 依赖升级到 **1.4.5**。

<Warning>
`setAudioModuleEnabled(false)` 期间**通话音频收不到也发不出**，本地播放结束后必须调回 `true`。重新入会会自动复位为 `true`，手动停用的状态不会跨会议泄漏。

做 iOS 全屏共享的工程，扩展 target 那条额外的 `srtc-swift-sdk` 依赖要**同步改为 `exact: "1.4.5"`**，与本包 pin 的版本保持一致，否则依赖解析冲突。
</Warning>

<Note>
`roomTitleDidChange` 的载荷**没有 `opUid`**：会议改名没有独立的广播指令，事件是频道属性更新后比对标题得出的，属性里只有结果没有操作者。后端补上对应广播指令后会再带上。

三个协议方法均带默认空实现，无破坏性变更，1.3.6 的接入代码可直接升级。

不要用 `connectionQualityDidChange` 代替收流状态事件：前者是整条链路的质量档位，不是某一路画面的卡顿，详见音视频 SDK 的[更新日志](/zh/rtc/swift/changelog)。
</Note>

### [1.3.6] - 2026.09.17
#### 新增
+ `MeetingUserInfo` 新增 `drawDisabled` 字段，可直接读取成员的涂鸦禁用状态。
+ 新增 `SMeetingDelegate` 的 `meeting(_:userDrawDisabledDidChange:)` 回调与 `UserDrawDisabledChangeEventData`，主持人改动成员涂鸦权限时触发，见[主持人管控](/zh/meeting/swift/advanced/host-controls)。

#### 变更
+ 此前仅有 `adminUpdateUserDrawDisabled(targetId:drawDisable:)` 这个设置接口，状态读取与变化事件缺失，涂鸦权限无法在业务侧完整实现，本版补齐。协议方法带默认空实现，无破坏性变更，1.3.5 的接入代码可直接升级。
+ SRTC 依赖保持 **1.4.4**。

### [1.3.4] - 2026.09.15
#### 新增
+ `startViewCaptureShare()`：创建并发布使用 `screen` 描述的自定义视频轨道，调用方可将视图渲染为 `CVPixelBuffer`，通过返回的 `LocalVideoTrack.pushFrame` 持续推帧。
+ `stopViewCaptureShare()`：停止视图录制视频轨道，不关闭或取消发布麦克风。使用方式与限制见[媒体控制接口](/zh/meeting/swift/api-reference/media-control#视图录制)。

#### 变更
+ SRTC 依赖保持 **1.4.3**，现有接入代码兼容；使用新增接口需将 SMeeting 升至 1.3.4。

### [1.3.2] - 2026.09.12
#### 新增
+ `requestShare(source:preset:view:messageOnly:byAdmin:adminUid:)`新增`excludedWindowIds`与`excludesCurrentApplication`两个带默认值的参数，透传给音视频层，用于 macOS 整屏共享时挖掉自家的某些窗口。现有调用点源码兼容。

#### 变更
+ 依赖的 SRTC 升级到 **1.4.2**：macOS 整屏共享改为默认**包含**本 App 自己的窗口（此前整个进程都被排除），并修复了「只共享屏幕音频时麦克风被一起发出去」，详见音视频 SDK 的[更新日志](/zh/rtc/swift/changelog)。

<Warning>
会中主窗口通常正在渲染远端画面。整屏共享放开自身窗口后，如果界面上有共享预览、或是同机双开自测，这类窗口会形成**无限镜像**。把它们的 ID（`UInt32(NSWindow.windowNumber)`）放进`excludedWindowIds`：

```swift
let ids = NSApplication.shared.windows
    .filter { $0.isVisible && $0.windowNumber > 0 }
    .map { UInt32($0.windowNumber) }
try await meeting.requestShare(source: chosen, excludedWindowIds: ids)
```

确实要回到旧的「整个 App 都不共享」行为，把`excludesCurrentApplication`置`true`。
</Warning>

<Note>
**iOS 全屏共享的扩展 target 那条额外依赖要跟着升到 1.4.2**：`.package(url: "https://github.com/seastart/srtc-swift-sdk.git", exact: "1.4.2")`。它必须与本 SDK 清单里 pin 的版本一致，否则依赖解析冲突，见[集成方式](/zh/meeting/swift/integration)。
</Note>

### [1.2.1] - 2026.09.07
#### 修复
+ 修复远端屏幕共享状态的判定：成员的`shareState`现在要求「房间共享状态（`share_state`/`share_uid`）+ 存在 screen 轨道」两者都满足才跃变为共享中，不再单凭轨道存在就判定。修掉了轨道先于房间状态到达时的误报，以及房间状态未变、轨道短暂消失时误报「共享已停止」。
+ 白板共享（`whiteBoard`）无媒体轨道，仍完全由房间 props 推导，行为不变。

#### 变更
+ 依赖的 SRTC 升级到 **1.3.2**（含 mqtt`content`为`null`的崩溃修复，以及`DeviceType.harmonyOS`）。

### [1.2.0] - 2026.08.20
#### 新增
+ iOS 全屏屏幕共享：新增`prepareBroadcastShare(appGroup:preset:)`、`publishBroadcastShare(view:byAdmin:adminUid:)`、`stopBroadcastListening()`、`requestShare(broadcastAppGroup:...)`与只读属性`isShareBroadcastActive`，可共享整个系统屏幕（此前 iOS 只能采到本 App 画面），需额外集成一个 Broadcast Upload Extension，详见[屏幕共享](/zh/meeting/swift/advanced/screen-sharing)；
+ 新增共享出帧事件`meeting(_:shareBroadcastDidStart:)`与`meeting(_:shareBroadcastDidFinish:)`，用于区分「监听已挂上」与「真的有画面了」，对应数据类型`ShareBroadcastStartEventData`、`ShareBroadcastStopEventData`；
+ iOS 音频路由：新增`defaultAudioRoute`（持久默认）、`setAudioRoute(_:)`与`clearAudioRouteOverride()`（临时切换），以及`currentAudioRoute`、`effectiveAudioRouteTarget`、`audioRouteOverride`、`isExternalAudioRouteActive`、`isAudioSessionActive`、`audioCallState`、`availableAudioRoutes()`等只读状态，详见[音频路由](/zh/meeting/swift/advanced/audio-routing)；
+ 新增音频路由事件`meeting(_:audioRouteDidChange:)`与`meetingAudioRouteDidRecoverFromInterruption(_:)`，对应数据类型`AudioRouteChangeEventData`；
+ 新增通话质量事件`meeting(_:didReceiveQualityReport:)`、`meeting(_:connectionQualityDidChange:)`、`meeting(_:activeSpeakersDidChange:)`、`meeting(_:didSwitchLayer:)`，数据结构直接复用 SRTC 的`QualityReport`、`ConnectionQualityChange`、`ActiveSpeakersSnapshot`、`LayerSwitchedInfo`。

#### 变更
+ 依赖`SRTC`升级至`1.3.0`（此前为`1.1.0`），随之带来公开 API 上错误枚举由`mqtt*`改名为`signaling*`等变化，详见音视频 SDK 的更新日志；
+ 屏幕共享的`roomShareDidStart`改为以 RTC 媒体轨道为准：远端 screen 轨道到达即上报，不再要求房间共享状态同时就位。

#### 修复
+ 修复远端成员开始共享后其它端收不到`roomShareDidStart`、共享画面不显示的问题（房间状态与媒体轨道到达顺序不定时，两条上报路径会互相拦掉）；
+ 修复共享方进程被杀、网络断开等情况下不上报`roomShareDidStop`，会议状态永久停在「某人正在共享」的问题；
+ 修复白板共享在房间状态先到达时重复上报`roomShareDidStart`的问题；
+ `exitRoom()`改为精确离开会议自己那一个 RTC 频道，不再影响调用方通过`meeting.srtc`另外加入的频道。

<Warning>
**iOS 上入会即申请麦克风权限、状态栏显示橙色指示点。** 会议加入后 SDK 会建立通话音频通道并保持到离会，即使成员只旁听、没有开麦。这是 iOS 上音频路由可控的前提（听筒输出只存在于可录音的会话类别下），与 Zoom、腾讯会议等 App 表现一致，不是 SDK 在录音。请确保`Info.plist`含`NSMicrophoneUsageDescription`，否则 App 会崩溃。
</Warning>

<Note>
**iOS 全屏共享的扩展 target 需要额外声明一条依赖。** `SRTCBroadcastKit`是音视频层`srtc-swift-sdk`的产物，SwiftPM 不允许使用传递依赖的产品，因此要在工程里再加一条`.package(url: "https://github.com/seastart/srtc-swift-sdk.git", exact: "1.3.0")`，并且**只加到扩展 target**上，见[集成方式](/zh/meeting/swift/integration)。
</Note>
