---
title: 服务端 API 通用说明
---

所有服务端接口均为 `POST` + JSON 请求体，成功与失败都返回 HTTP 200，业务结果由响应体的 `code` 判定（`0` 表示成功）。

### 鉴权

除少数公开接口外，均需在请求头携带以下四个字段：

| 请求头 | 必填 | 说明 |
| --- | --- | --- |
| `app_id` | 是 | 应用 ID。也接受 `app-id` 或 `appid`，用于兼容部分语言/网关不支持下划线的情况 |
| `nonce` | 是 | 随机字符串，每次请求不同，用于防重放 |
| `timestamp` | 是 | 秒级时间戳。与服务端时间偏差需在 ±300 秒内，否则返回时间戳无效 |
| `signature` | 是 | 请求签名，算法见下 |

签名算法：把待签名串用 `app_key` 做 HMAC-SHA256（结果为小写十六进制字符串）。

```
待签名串 = "{appidName}={app_id}&nonce={nonce}&timestamp={timestamp}&{body}"
signature = HMAC-SHA256(app_key, 待签名串)
```

其中：

+ `{appidName}` 必须与你实际使用的请求头名保持一致（用了 `app-id` 就写 `app-id`）
+ `{body}` 是**原始请求体字符串**，需与实际发送的字节完全一致（包括空格与字段顺序），不要重新序列化
+ `app_key` 只用于本地计算签名，**绝不能出现在请求中，也不能下发到客户端**

### 关于 uid 与 sid

+ `uid` 是你自己业务的用户 ID，由你指定，RTC 侧不生成
+ `sid` 是本次会话 ID，由 RTC 侧在授权时生成，同一 `uid` 多次进入会有不同的 `sid`
