### Request parameters

#### MeetingCreateReq

Parameters for creating / updating a meeting. To construct:

```swift
var req = MeetingCreateReq(title: "Weekly project sync", meetingMode: .normal)
req.meetingType = .appointment
req.planTime = Int(Date().timeIntervalSince1970) + 1800
req.planDur = 60
```

| Field | Type | Description |
| --- | --- | --- |
| `title` | `String` | Meeting title (required when constructing) |
| `meetingMode` | `MeetingMode` | Meeting mode (required when constructing) |
| `roomNo` | `String?` | Custom room number; generated by the server if omitted |
| `content` | `String?` | Meeting description |
| `meetingType` | `MeetingType?` | Meeting type; treated as an instant meeting if omitted |
| `planTime` | `Int?` | Scheduled start time, timestamp in seconds |
| `planDur` | `Int?` | Meeting duration, in minutes |
| `attendType` | `AttendType?` | Entry restriction type |
| `password` | `String?` | Meeting password; required for password-protected entry |
| `conferee` | `[String]?` | Invitee IDs; required only for invitation-only entry |
| `coHosts` | `[String]?` | Co-host IDs |
| `maximum` | `Int?` | Maximum number of members |
| `endType` | `EndType?` | How the meeting ends |
| `entryMutePolicy` | `EntryMutePolicy?` | Mute-on-entry policy |
| `watermarkDisabled` | `Bool?` | Whether to turn off the watermark |
| `screenshotDisabled` | `Bool?` | Whether to prevent screenshots |
| `chatDisabled` | `Bool?` | Whether to disable chat for everyone |
| `waitingRoomDisabled` | `Bool?` | Whether to turn off the waiting room |
| `enterBeforeHostDisabled` | `Bool?` | Whether to prevent entering before the host |
| `autoRecord` | `Bool?` | Whether to record automatically |
| `layoutData` | `LayoutData?` | Composite layout |
| `background` | `String?` | Resource key of the background image |
| `attachments` | `[Attachment]?` | Meeting materials |
| `extendInfo` | `String?` | Business extension field; a JSON string is recommended |

#### Layout and recording parameters

`McuStartReq`, `LayoutData`, `Watermark`, `Tag`, `Cell`, `DivList`, and `Attachment` all provide initializers whose optional parameters have default values; they're also `Codable`, so you can decode them from JSON delivered by your backend with `JSONDecoder`. For the mapping between fields and JSON keys, see [Recording and composite layout](/en/meeting/swift/advanced/recording).

#### AgentInfo

A device that can be invited, returned by `agentList(...)`.

| Field | Type | Description |
| --- | --- | --- |
| `id` | `String` | Device ID |
| `name` | `String` | Device name |
| `type` | `AgentType` | Device type |
| `status` | `AgentStatus` | Device status; see [AgentStatus](#agentstatus) for values |
| `contact` | `String` | Device identifier, passed to `adminInviteAgent(...)` when inviting |
| `remark` | `String` | Remark |
| `connParams` | `[String: AnyCodable]?` | Connection parameters (backend `conn_params`), passed through as is; `nil` when absent |
| `connSubjects` | `[String: String]` | GB28181 channel table (`conn_params.subjects`, `{channel number: channel name}`); empty when absent |

`connParams`, `connSubjects`, and the public initializer `AgentInfo(id:name:type:status:contact:remark:connParams:)` (`remark` and `connParams` have default values) are available since 1.5.0.

GB28181 devices must be invited as "device number:channel number"; passing `contact` directly is rejected by the backend. The SDK only parses the channel table and doesn't expand it for you. Typically, list one row per GB28181 channel:

```swift
for (channelNo, channelName) in agent.connSubjects {
    let contact = "\(agent.contact):\(channelNo)"   // use this when inviting
    let title = "\(agent.name)(\(channelName))"
}
```

Except for `type`, missing fields decode to empty values, so bad data from one device no longer makes the whole device list fail to decode.

#### MeetingToken

The parsed contents of the login token. You usually don't need it—the token is issued by your backend, and you just pass it to `login(token:)`. If you need to check on the client in advance whether the token has expired, you can:

```swift
let info = try MeetingToken.decode(from: token)
if info.isExpired { /* Get a new one from your backend */ }
```

| Field | Type | Description |
| --- | --- | --- |
| `appId` | `String` | App ID |
| `userId` | `String` | User ID |
| `nickname` | `String` | Nickname |
| `expAt` | `Int` | Expiration time, timestamp in seconds |
| `isExpired` | `Bool` | Whether it has expired |

#### AgentStatus

| Enum value | Raw value | Description |
| --- | --- | --- |
| `unknown` | `0` | Unknown |
| `online` | `1` | Online |
| `offline` | `2` | Offline |

Values match the server; any other value from the backend decodes to `.unknown`. The definition in 1.4.1 and earlier was wrong (`idle = 1` idle, `busy = 2` busy, `offline = 3` offline), and the whole device list failed to decode when the backend sent `status = 0`. Fixed in 1.5.0:

+ `idle` and `busy` remain as deprecated aliases for `.online` and `.offline` respectively, so existing code still compiles
+ **The raw value of `offline` changed from `3` to `2`**: check any code that compares `rawValue` numerically or has persisted raw values

### Types from SRTC

The following types are defined in the underlying SRTC module and require `import SRTC` to use: `LogLevel`, `CameraPreset`, `MicPreset`, `ScreenPreset`, `DeviceInfo`, `DisconnectReason`, `ImDisconnectReason`, `AnyCodable`, `SRTCVideoView`, `SRTCVideoRenderer`, `ScreenCaptureSources`, `DisplaySource`, `WindowSource`, `LocalCameraTrack`, `LocalScreenTrack`, `RemoteVideoTrack`, `Track`, `SRTCBroadcastPicker`.

`NativeVideoView` is an alias SMeeting defines for the render view; its actual type is `SRTCVideoRenderer`.

#### Audio routing (iOS)

| Type | Description |
| --- | --- |
| `AudioRoute` | The system's actual output route, **read-only with five states**: `unknown` / `speaker` (speakerphone) / `receiver` (earpiece) / `bluetooth` / `headset`. Also has `displayName`, `isBuiltIn`, and `isExternal` |
| `AudioRouteTarget` | The target you can actively switch to, **with only two states**: `speaker` / `earpiece` |
| `AudioRouteInfo` | A port snapshot (for diagnostics): `id`, `route`, `name`, `isActive` |
| `AudioCallState` | System call state: `unknown` / `dialing` / `incoming` / `connected` / `disconnected` |

For why there are only two switchable states, see [Audio routing](/en/meeting/swift/advanced/audio-routing).

#### Call quality

| Type | Fields |
| --- | --- |
| `ConnectionQuality` | Quality level: `unknown` / `excellent` / `good` / `poor` / `lost` |
