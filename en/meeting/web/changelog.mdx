### v0.3.9 - 2026-11-25

#### Added
+ **Simultaneous interpretation for meetings**: the host / co-host turns interpretation on and off with `startInterp()` / `stopInterp()` (transcription is turned on first automatically if it isn't on), and each member sets "my language" with `setMyInterpLang(lang)`. The server translates each sentence into the languages of the members in the meeting and synthesizes speech. The Web SDK has a built-in interpretation player that plays interpretation audio in my language one after another, lowering the speaker's original voice while it plays (the volume comes from the AI profile, default 20%) and restoring it afterward; `setInterpListenOriginal(true)` switches to listening to the original voice only, without affecting captions. See [SMeeting · Simultaneous interpretation](/en/meeting/web/api-reference/SMeeting#simultaneous-interpretation) for usage
+ Added the room events `ROOM_INTERP_STATE_CHANGED` (interpretation turned on/off) and `USER_INTERP_LANG_CHANGED` (a member's language changed), see [Events](/en/meeting/web/events); re-emitted automatically after reconnecting if anything changed
+ Added `isInterpEnabled()`, `getMyInterpLang()`, `getUserInterpLang(uid)`, `getInterpLangs()`, and `isInterpListenOriginal()`; `RoomInfo` adds `interp_enabled`, `interp_duck_volume`, `interp_langs`, and `interp_default_lang`
+ `ASR_TRANSLATION` adds `audio_url` (interpretation audio URL, present only when interpretation is on and synthesis succeeded). When interpretation is on, each sentence arrives once per language of the members in the meeting; filter by `lang` to my language when showing captions
+ The underlying SRTC dependency is upgraded to Web `^0.7.7`

<Warning>
When interpretation is on, each sentence is delivered as multiple translations with different `lang` values, and older clients that don't filter by `lang` show all of them as captions. Upgrade all meeting clients before enabling interpretation; if there's a reverse proxy on site, allow the `/aiapi/interp-audio/` path, otherwise you get captions only and no interpretation audio.
</Warning>

### v0.3.8 - 2026-11-24

#### Added
+ **Pre-call network check `networkCheck`**: call it before entering a meeting, without entering; no parameters are needed when logged in (when not logged in, pass the meeting token, or `appId` + `serverUrl`). The five checks (network permission, network connection, MTU, DNS resolution, server connectivity) are done by the SRTC layer and passed through as is; the meeting layer additionally checks in the server connectivity item whether the meeting API is reachable. `onItem` reports progress item by item, and the call finally returns a summary, with each item carrying a description you can show to users directly. Call `cancelNetworkCheck()` to cancel. See [SMeeting · Pre-call network check](/en/meeting/web/api-reference/SMeeting#pre-call-network-check) for usage and [Pre-call network check types](/en/meeting/web/types#pre-call-network-check-types-since-0-3-8) for the types
+ The underlying SRTC dependency is upgraded to Web `^0.7.6`

### v0.3.7 - 2026-11-24

#### Added
+ Added `getLocalCameraTrack()` / `getLocalScreenTrack()` to get the local camera and screen-share tracks, alongside the existing `getLocalMicTrack()`
+ Added `subscribeRemoteAudioMixTrack()` to get the remote audio mix (everyone except you); use it with `createLocalCompositeRecorder()` for local recording. There is only one mix per meeting: if it is already playing, the same track is returned and nothing is subscribed twice
+ Added the room event `ADMIN_REQUEST_OPEN_SHARE`: the host asks you to share your screen. To accept, call `requestShare()` with `byAdmin = true` and `adminUid = data.op_uid`

#### Fixed
+ Fixed an issue where calling `requestShare()` with `byAdmin = true` and an empty `adminUid` sent the screen but didn't update the meeting's sharing state

### v0.3.6 - 2026-11-18

#### Added
+ **Live captions and translation**: the host turns meeting transcription on and off with `adminAsrStart(translateLang?)` / `adminAsrStop()`; `isAsrEnabled()` returns the current state. Changes fire the room event `ROOM_ASR_STATE_CHANGED`; captions and translations arrive via `ASR_RESULT` and `ASR_TRANSLATION`. `RoomInfo` gains `asr_enabled`
+ **Meeting minutes**: `aiSummary(meetingId?)` returns each transcription session and its minutes (also after the meeting); the host can regenerate them with `adminAiSummaryGenerate(sessionId, meetingId?, templateId?)`. `AI_SUMMARY_READY` fires when minutes finish or fail
+ **Transcripts**: `aiTranscript(meetingId?, sessionId?)` returns the raw transcript, grouped by session with sentences in time order

### v0.3.5 - 2026-11-18

#### Added
+ **Capture-only preview (device checks)**: `requestOpenCamera()` / `requestOpenMic()` gain a trailing `publish` parameter. With `false` they only capture and preview, without asking the meeting for permission, publishing, or firing state events; they work before and during a meeting. Calling again with `publish: true` promotes the track and publishes the same track without restarting capture. See [Device checks](/en/meeting/web/advanced/device-check)
+ `requestOpenMic()` returns the local mic track (`LocalMicTrack`), so you can read the volume with `getVolume()` directly
+ Added `isCameraOpened()` / `isMicOpened()`: whether the camera / mic is open as the meeting camera / mic; `false` during a preview only

#### Fixed
+ Fixed an issue where a camera or mic opened before entering a meeting couldn't be published after entering: calling `requestOpenCamera()` / `requestOpenMic()` again reported "already on". It is now published

### v0.3.4 - 2026-11-18

#### Added
+ **AI noise suppression**: added `setAudioProcessor()`, which hands microphone audio processors such as `@seastart/srtc-plugin-deepfilternet` to the meeting layer; from then on they are attached every time the mic opens and detached when the mic closes or you leave the meeting. See [AI noise suppression](/en/meeting/web/advanced/deepfilternet)
+ Upgraded the underlying SRTC dependency to Web `^0.7.3`

### v0.3.3 - 2026-11-12

#### Fixes
+ **Entering again after being removed, replaced by another login, or after the meeting ended failed with "already in a meeting" (`206006`)**: after `DISCONNECTED`, the SDK used to keep its meeting state until your code called `exitRoom()`. Without that call, a later `enterRoom` on the same SDK instance was rejected locally and never reached the server. The SDK now clears the state itself once the `DISCONNECTED` callback returns, so you can call `enterRoom` again directly. Calling `exitRoom()` in the callback still works, so existing code needs no change

### v0.3.2 - 2026-11-09

#### Fixes
+ **Custom out-of-meeting (IM) messages never reached the callback**: messages sent with the server API [`im/send-msg`](/en/rtc/server-api/im#send-an-im-message) whose `action` is not one of the SDK's built-in types used to be silently dropped, so `onNotifyImEvent` never fired. They are now delivered through the new `CommonImEventType.IM_CUSTOM_MSG` event, with `data` of type `ImCustomMsgEventData` (`action`, `content`, and the sender's `uid` / `name` / `sid`). See [Events · Out-of-meeting message events](/en/meeting/web/events#out-of-meeting-message-events)
+ Removed a stray console log printed for every incoming IM message

### v0.3.1 - 2026-11-04

+ **Works with webpack 4 and other older toolchains**: the build output is now down-leveled to ES2019, and the ESM build is renamed from `smeeting.mjs` to `smeeting.esm.js` (the `module` / `exports` fields in `package.json` are updated, so regular `import` statements are unaffected). This fixes the `Module parse failed` and `Can't import the named export ... from non EcmaScript module` errors with webpack 4's default configuration. APIs and runtime behavior are unchanged
+ The underlying SRTC is upgraded to Web 0.7.1, which is down-leveled to ES2019 as well; see the [SRTC Web changelog · v0.7.1](/en/rtc/web/changelog)

### v0.3.0 - 2026-09-30

<Warning>
**This release contains breaking changes**: meeting-layer error codes are renumbered, the SDK's error messages are now in English, and a `language` parameter is added. Any code that branches on the numeric `code` (especially `206000`) or on Chinese error text needs to be updated according to the table below. For the full tables, see [Error codes](/en/meeting/web/error-codes) and [Error code format and unified table](/en/meeting/error-codes). The underlying SRTC is upgraded to Web 0.7.0 as well, and the `106xxx` codes it passes through are also renumbered; see the [SRTC Web changelog · v0.7.0](/en/rtc/web/changelog).
</Warning>

#### Breaking changes
+ **Meeting-layer error codes renumbered**: low 3-digit codes are assigned from the cross-platform unified table instead of falling into `206000`. Check `code`, not the message text
+ **Error messages in English**: the `message` / `msg` of the SDK's own errors are now all in English and meant for developers and logs; map codes to your own end-user messages (the error code page has a "Suggested user message" column)
+ Network failures / HTTP non-200 responses when calling the meeting server are now always `206007`, with the HTTP status in `message`; unparsable responses or responses missing the `code` field are `206356`
+ Capture / permission errors pass through the SRTC-layer codes unchanged (such as `106231` camera permission denied, `106251` microphone permission denied, and `106039` screen sharing denied), and the cleanup after a failed turn-on no longer overwrites the original error
+ `McuTaskStatus` values now match the server: `WaitStart = 0` and `WaitEnd = 2` are added, `Exception` changes from 2 to 3, and `Normal` from 3 to 4. Code that compares by member name gets the correct meaning after upgrading; **check any code that compares against the literal numbers 2 / 3**

#### New
+ **`language`** init parameter (for example `zh-CN` or `en`; if omitted, follows `navigator.language`, falling back to `zh`), which also applies to the underlying SRTC: requests to both the meeting server and the SRTC server carry `Accept-Language`, and **the messages of server business errors (`1000`–`99999`) come back in Chinese or English accordingly**. The SDK's own errors are always in English and aren't affected. See [Types](/en/meeting/web/types)
+ `autoPlayDialogText` init parameter: overrides the text of the autoplay prompt (by default Chinese or English according to `language`)
+ The package exports `SdkError` and `MeetingErrorCode` (meeting-layer low 3 digits). The SRTC package also exports an `SdkError` with the same name; alias one of them when importing both packages

#### Fixes
+ The `McuRecordDetail` type now matches what the server actually returns: fields such as `began_at` / `total_duration` / `records` are added, and `mcu_at` / `mcu_dur` are deprecated (the server still fills them in; new integrations should use `began_at` / `total_duration`)

#### Changes
+ The SRTC dependency is upgraded to `@seastart/srtc-web-sdk` 0.7.0
+ The npm page description is now bilingual (Chinese and English), and the license is now proprietary (UNLICENSED)

#### Old code → new code mapping

| Scenario | 0.2.0 and earlier | 0.3.0 |
| --- | --- | --- |
| Not logged in / token expired / not in a meeting / no permission (host operations) | `206001` / `206002` / `206003` / `206004` | Unchanged (message now in English) |
| The room has disabled turning on the camera / mic / screen sharing | `206000` | `206004` |
| The token can't be parsed | Raw parse exception | `206005` |
| Already in a meeting, entering again | `206000` | `206006` |
| Network failure / HTTP non-200 when calling the meeting server | `Error` with no code | `206007` |
| No such member in the meeting | `206000` | `206010` |
| Turning on the camera / mic / screen sharing when it's already on, switching devices before it's on, and so on | `206000` | `206011` |
| Unparsable response / missing the `code` field | Raw parse exception / treated as a server error | `206356` |
| Capture / permission / publish and subscribe failures (passed through from SRTC) | Old SRTC codes or the browser's raw exception | New SRTC codes such as `106231`, `106251`, `106039`; see the [SRTC Web changelog](/en/rtc/web/changelog) |
| Server business errors (`1000`–`99999`) | Passed through | Passed through; messages come back in Chinese or English according to `language` |
