### [2.1.0] - 2026.09.08
#### Added
+ `MeetingKit` adds virtual background: `installVirtualBackground:`, `uninstallVirtualBackground`, `enabledVirtualBackground:`, `setVirtualBackgroundBlur:`, `setVirtualBackgroundImage:`, `setVirtualBackgroundInferenceInterval:`, `setVirtualBackgroundMaskSync:`, and `isVirtualBackgroundEnabled`. It performs person segmentation and then blurs or replaces the background, and **installing it doesn't require a license key**.
+ Virtual background applies to the single shared camera capture pipeline in the process. It's a device-level setting that applies to all rooms at once. After a camera switch during the meeting or a reconnect, the SDK automatically re-applies the current configuration, so your app doesn't need to do it. For usage, see [Virtual background](/en/meeting/ios/advanced/virtual-background).
+ `SEADeviceType` adds `SEADeviceTypeHarmonyOS` (`8`) to identify HarmonyOS members.
#### Changed
+ The minimum OS requirement is raised from iOS 10.0 to **iOS 16.0**.
+ The `RTCEngineKit` dependency is upgraded to `3.1.0`, and the podspec's minimum dependency is raised from `>= 3.0.0` to `>= 3.1.0`. The virtual background inference engine `onnxruntime-c` is pulled in transitively through the `RTCEngineKit` podspec, so you don't need to declare it explicitly in your `Podfile`.
#### Fixed
+ Picks up the local preview fix in `RTCEngineKit 3.1.0`: with virtual background on, the local preview now shows the processed video, matching what the other side sees. Previously the local side could only see the raw camera video.
+ Picks up the fix in `RTCEngineKit 3.1.0` for video freezing caused by the pre-processing output buffer being released too early and the display buffer conflicting with writes of the next frame.

<Warning>
This release contains breaking changes: your project's `IPHONEOS_DEPLOYMENT_TARGET` and the `platform :ios` in your `Podfile` must be at least 16.0; otherwise the dependency can't be resolved. No existing public APIs or callback signatures of `MeetingKit` and `MeetingKitRoom` were removed or changed, so existing code doesn't need to be rewritten.
</Warning>

### [2.0.0] - 2026.08.12
#### Added
+ Added the meeting room instance class `MeetingKitRoom`, which carries all in-meeting capabilities: entering and exiting rooms, local audio, video, and sharing, chat and raise hand, host management, cloud recording, the waiting room, sub-meetings, sign-in, and room data queries.
+ Added the room event protocol `MeetingKitRoomDelegate`, which carries all in-room events.
+ `MeetingKit` adds `createRoomWithDelegate:` and `getRooms` to create room instances and query the rooms you have entered.
+ `MeetingKitRoom` adds `publishLocalVideo:` and `enabledSendAudio:` to control publishing of local video and audio per room.
+ `MeetingKitRoomDelegate` adds the `meetingRoom:onUserUpdate:` callback for updates to your own data and the `meetingRoom:onReceiveCustomMessage:action:userId:sessionId:nickname:` callback for room custom messages.
#### Changed
+ `MeetingKit` is narrowed down to a global singleton that keeps only login and logout, IM, meeting queries and scheduling, device lists, local capture preview, audio routing, and screen capture process integration.
+ `enterRoom:onSuccess:onFailed:`, `exitRoom:`, `callUser:onSuccess:onFailed:`, `requestOpenCamera:view:onSuccess:onFailed:`, `requestShare:onSuccess:onFailed:`, `sendRoomChatMessage:messageType:targetId:onSuccess:onFailed:`, `switchSpeaker:`, `enabledAudioModule:`, `startRemoteView:streamType:view:`, the `adminXxx` family, and the cloud recording, waiting room, sub-meeting, sign-in, room data query, and media configuration APIs move from `MeetingKit` to `MeetingKitRoom`.
+ `MeetingKitDelegate` keeps only two global events: `onAudioRouteChange:previousRoute:` and `onApplicationPerformance:cpuUsage:`.
+ The other in-meeting callbacks move to `MeetingKitRoomDelegate` and all carry the source room instance as the first parameter. For example, `onEnterRoom:userId:` becomes `meetingRoom:onEnterRoom:userId:`, `onUserMicStateChanged:micState:reason:` becomes `meetingRoom:onUserMicStateChanged:micState:reason:`, and `onReconnecting` becomes `meetingRoomOnReconnecting:`.
+ The `RTCEngineKit` dependency is upgraded to `3.0.0`, and the podspec's minimum dependency is raised from `>= 2.5.0` to `>= 3.0.0`.
#### Improved
+ The same account can create multiple room instances at once and enter multiple rooms. Each room's media and business state is independent, and member data for the same userId across rooms is isolated per room.
+ Camera capture and preview, audio routing, and screen capture are managed centrally by `MeetingKit` as shared device capabilities; whether they are pushed to a given room is controlled separately by that room instance.
+ `logout` exits and destroys all room instances before releasing resources, so your app doesn't need to exit each room one by one.

<Warning>
This release contains breaking changes. Your app must hold room instances through `createRoomWithDelegate:`, rewrite all in-meeting API calls, and migrate in-meeting callbacks to the new `MeetingKitRoomDelegate` signatures; otherwise the related APIs won't compile and the callbacks will no longer fire.
</Warning>
