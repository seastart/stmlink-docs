### [2.5.0] - 2026.11.25

#### Added
+ **Force-join flag in call events**: `MeetingKitIMDelegate` adds the optional callback `onCallReceived:nickname:roomNo:title:meetingId:forceJoin:`, which carries the meeting ID `meetingId` and `forceJoin` in addition to the original callback. `forceJoin` maps to the `force_join` parameter of the server call users API; `YES` means the administrator requires the callee to join directly, so the app can skip the answering UI and join the meeting. See [MeetingKitIMDelegate](/en/meeting/ios/api-reference/MeetingKitIMDelegate#oncallreceivednicknameroomnotitlemeetingidforcejoin).

<Note>
Once you implement the new callback, the SDK no longer calls the old `onCallReceived:nickname:roomNo:title:`; if you don't, the old method is still called and existing API signatures are unchanged. The `RTCEngineKit` dependency is still `>= 3.3.0`, so 2.4.0 integrations can upgrade without code changes.
</Note>

### [2.4.0] - 2026.11.25

#### Added
+ **Presigned resource upload / download**: `MeetingKit` adds `presignedPutObject:meetingId:ext:onSuccess:onFailed:` and `presignedGetObjectWithResKey:resId:onSuccess:onFailed:` for uploading resources such as chat files directly to storage. See [MeetingKit](/en/meeting/ios/api-reference/MeetingKit#resource-apis).
  + Presigned upload returns [SEAPresignedPutObjectModel](/en/meeting/ios/types#seapresignedputobjectmodel) (`url` / `key` / `ext`) in the success callback; the caller uploads the file bytes to `url` with an HTTP PUT (`Content-Type: application/octet-stream`, not multipart). Store and send the `key` in your business logic
  + Presigned download returns the download URL string in the success callback. The URL is signed and expires in about 2 hours; request a new one before each download and don't cache it
  + `resId` is a reserved parameter that **the backend doesn't support yet; pass `resKey`**. If `resKey` is empty, the failure callback is invoked immediately with `SEAErrorMeetingInvalidArgument` (`203012`)
  + Chat file message convention: after uploading, send the JSON string `{"key":"<key>","name":"original file name","size":"1.20MB"}` as an `SEAMessageTypeFile` message, consistent with other platforms
+ Added the enum [SEAResourceType](/en/meeting/ios/types#searesourcetype) (`Attach` / `Background` / `User` / `Chat`); pass `SEAResourceTypeChat` for chat files.
+ Added the backend business code `SEAErrorMeetingApiFileDisabled` (`2125`): presigned upload returns it when the deployment has disabled the file feature.

#### Fixed
+ In `MeetingKitRoom`, `getMoreOnlineMemberList:onSuccess:onFailed:` requested the chat message list API from the second page on, so later pages of online members couldn't be fetched. It now requests the online member list API.

<Note>
This release only adds APIs and fixes; existing API signatures are unchanged and the `RTCEngineKit` dependency is still `>= 3.3.0`, so 2.3.0 integrations can upgrade without code changes.
</Note>

### [2.3.0] - 2026.11.25

#### Added
+ **Pre-call network check**: `MeetingKit` adds `networkCheck:onItem:completion:` and `cancelNetworkCheck`. Call it before joining; it doesn't require entering a room or connecting to RTC. The check logic is the same as SRTC's: items are checked in the fixed order `permission` → `connectivity` → `mtu` → `dns` → `server`, `onItem` is called on the main thread as each item completes, and the overall result is delivered on the main thread (`ok` / `warning` / `fail`; each item carries a machine-readable `reason` and a Chinese `message` ready for display). When everything is normal it finishes within about 5 seconds, and takes at most about 10 seconds. See [MeetingKit](/en/meeting/ios/api-reference/MeetingKit#pre-call-network-check-apis) and [Types](/en/meeting/ios/types#seanetworkcheckresult).
  + **The `server` item has an extra `meeting_api` subcheck**: it checks whether the meeting API is reachable, and any HTTP response counts as reachable. If unreachable, `server` is `fail` with `reason` `meeting_api_unreachable` (if `server` has already failed because of an RTC subcheck, the RTC reason is kept). When not logged in, `meeting_api` is `skipped` (`server_info_unavailable`)
  + When logged in, `params` can be `nil`; when not logged in, pass `appId` + `serverUrl` or an RTC `token`, otherwise `SEAErrorMeetingNotLoggedIn` (`203001`) is returned
  + A check already running returns `SEAErrorConflict` (`103005`); invalid parameters or an undecodable token return `SEAErrorInvalidArgs` (`103031`); when cancelled by `cancelNetworkCheck` or by logging out, the completion callback finishes with `SEAErrorUserCancelled` (`103026`). All of these are RTC layer codes passed through
  + Added the meeting-layer types `SEANetworkCheckParams`, `SEANetworkCheckItem`, `SEANetworkCheckResult` and the string constants `SEANetworkCheckItemId`, `SEANetworkCheckStatus`, `SEANetworkCheckReason`, with the same values as on other platforms

#### Changed
+ The `RTCEngineKit` dependency is upgraded to `3.3.0`, and the podspec minimum is raised from `>= 3.2.1` to `>= 3.3.0`. If your `Podfile` pins a lower `RTCEngineKit` version, relax it as well; otherwise the dependency can't be resolved.

<Note>
This release only adds APIs; existing APIs and behavior are unchanged. The RTC API check in `server` requires server-side support for the pre-call network check; if the server hasn't been upgraded, the RTC `api` subcheck is `fail`, and other items are unaffected.
</Note>

### [2.2.1] - 2026.10.08

#### Changed
+ **`language` also sets the RTC layer**: setting `MeetingKit.language` also sets `RTCEngineKit.language`, so meeting-layer and RTC layer requests to the backend use the same `Accept-Language`. The 2.2.0 limitation that "RTC layer requests don't carry a language yet" is lifted.
+ **Backend business codes passed through from the RTC layer carry the server-side message**: when the RTC layer returns a backend business code in `1000`–`99999`, the error description now uses the message returned by the server (language follows `language`); previously it was the generic `Server rejected the request`.
+ The `RTCEngineKit` dependency is upgraded to `3.2.1`, and the podspec minimum is raised from `>= 3.2.0` to `>= 3.2.1`.

<Note>
No public APIs were removed or changed, so 2.2.0 integrations need no code changes. If your project explicitly pins `RTCEngineKit 3.2.0`, MeetingKit still runs, but RTC layer requests carry no language; we recommend upgrading to `3.2.1` as well.
</Note>

### [2.2.0] - 2026.10.08
<Warning>
**This release has breaking changes. Read this whole section before upgrading**: errors produced by the meeting layer itself now use `203`-range error codes (same codes and meanings as the Swift SDK), RTC layer error codes passed through are renumbered along with `RTCEngineKit 3.2.0`, and error messages are now in English. Any code that branches on the **numeric value** of `SEAError`, on old constants such as `SEAErrorNetError`, or on the Chinese text of `message` needs to be adjusted. The one place to check first: **meeting-layer network failures no longer return `SEAErrorNetError`**, so a "network error" prompt written as `code == SEAErrorNetError` will stop working entirely after the upgrade.
</Warning>

#### Must read before upgrading
+ **Meeting-layer errors use the 203 range**: errors produced by the meeting layer itself are now the iOS prefix `203` + low 3 digits of the unified table (`203001`–`203012`, `203209`, `203353`–`203356`), with the same codes and meanings as the Swift SDK. For the meaning of each code, see [Error codes](/en/meeting/ios/error-codes) and [Error code format and unified table](/en/meeting/error-codes).
+ **Meeting-layer network failures no longer return `SEAErrorNetError` (`100009`)**: request failures / non-200 HTTP now return `SEAErrorMeetingNetworkError` (`203007`); timeouts `203353`; cancellations `203354`; an empty response body `203355`; a response that isn't JSON or lacks the `code` field `203356`. The value of the `SEAErrorNetError` constant also changed to `103006`, and it now only means an RTC layer network error.
+ **Backend business failures pass through the backend business code**: previously, when the backend rejected a request, the callback always returned `100009`; now it returns the backend's business code as is (e.g. `2101` meeting doesn't exist, `2115` wrong password), with `message` set to the backend's `msg`, in the language set by `language`.
+ **Meeting token decoding failure**: when the token passed to `loginWithToken:...` can't be decoded, the code changes from `SEAErrorApiTokenDisabled` (`10042`) to `SEAErrorMeetingTokenInvalid` (`203005`).
+ **Entering twice / destroyed instance**: calling `enterRoom:onSuccess:onFailed:` while joining or already joined changes from `SEAErrorApiRepeatFound` (`10003`) to `SEAErrorMeetingAlreadyInMeeting` (`203006`); when the room instance has been destroyed, it changes to `SEAErrorMeetingInvalidState` (`203011`).
+ **APIs that only the host / co-host can call**: when called by a non-admin, the code changes from `SEAErrorNotAuthorized` (`103005`) to `SEAErrorMeetingUnauthorized` (`203004`).
+ **Device permissions**: `SEAErrorDeviceNoAuthorized` no longer occurs; missing camera permission now returns `SEAErrorCameraNoAuthorized` (`103231`), and missing microphone permission returns `SEAErrorMicNoAuthorized` (`103251`).
+ **RTC layer codes renumbered**: RTC layer error codes passed through (formerly `100001`–`100012`, `103001`–`103005`) are now `103` + low 3 digits of the unified table along with `RTCEngineKit 3.2.0`, with the same values as `RTCEngineError`. Enum names are unchanged but values changed, so you need to recompile. Note that old numbers are **reused for other meanings** in the new table (e.g. `103005` is now `SEAErrorConflict` and `103001` is now `SEAErrorNotJoinedChannel`), so checks hardcoded with numeric literals will be misaligned across the board. The `errCode` of `onError` and `onImDisconnected` is affected in the same way.
+ **`startRemoteView:streamType:view:` / `stopRemoteView:streamType:`**: when the user is in the meeting but doesn't have the video stream to subscribe to, the return value changes from the RTC layer's `RTCEngineErrorStreamNotFound` (`103004`) to `SEAErrorMeetingRemoteTrackUnavailable` (`203209`).
+ **Virtual background return values**: for `installVirtualBackground:`, installing twice changes from `SEAErrorConflict` to `SEAErrorVirtualBackgroundAlreadyInstalled` (`103027`), a missing model file from `SEAErrorNotFound` to `SEAErrorVirtualBackgroundModelNotFound` (`103029`), and inference session creation failure from `SEAErrorSystemError` to `SEAErrorVirtualBackgroundSessionFailed` (`103030`); calling `enabledVirtualBackground:` before installation changes from `SEAErrorConflict` to `SEAErrorVirtualBackgroundNotInstalled` (`103028`).
+ **Error messages are now in English**: `message`s produced by the SDK itself are always in English (those passed through from the RTC layer include the RTC code) and are meant only for developers and logs. For prompts to end users, map `code` yourself; don't show `message` directly.

#### Added
+ `MeetingKit` adds the `language` property (a BCP 47 language tag such as `@"zh-CN"` or `@"en"`; `nil` or an empty string means following the system) and the read-only `currentLanguage`. Priority: **developer setting > system's preferred language > `zh`**. Meeting-layer requests to the backend carry `Accept-Language`, so backend business error messages (`1000`–`99999`) come back in Chinese or English; the SDK's own errors are always in English and unaffected. It applies process-wide and isn't reset by login / logout; we recommend setting it before login.
+ `SEAError` adds the meeting-layer error codes `SEAErrorMeetingXxx` (`203xxx`) and the new RTC layer codes `SEAErrorUserCancelled`, `SEAErrorVirtualBackgroundXxx`, `SEAErrorSwitchAudioRouteFail`, `SEAErrorCameraNoAuthorized`, and `SEAErrorMicNoAuthorized`.

#### Changed
+ `SEAErrorNotAuthorized` is deprecated and is now a same-value alias of `SEAErrorMeetingUnauthorized` (`203004`); `SEAErrorMediaNotInitialized` is deprecated and is now a same-value alias of `SEAErrorNotInitialized` (`103024`). **Writing a pair of same-value constants in a `switch` causes a duplicate `case` error**; referencing a deprecated constant produces a deprecation warning, and projects with `-Werror` (or `Treat Warnings as Errors`) enabled fail to compile, so use the new names.
+ `language` doesn't apply to the RTC layer yet: `RTCEngineKit 3.2.0` doesn't provide a language setting, so the RTC layer's own requests carry no `Accept-Language`.
+ The `RTCEngineKit` dependency is upgraded to `3.2.0`, and the podspec minimum is raised from `>= 3.1.0` to `>= 3.2.0`.

#### Fixed
+ Fixed a crash when the `code` field of a backend response is `null` (or an object or array); it now calls back with `203356` (response parse failure).

### [2.1.0] - 2026.09.08
#### Added
+ `MeetingKit` adds virtual background: `installVirtualBackground:`, `uninstallVirtualBackground`, `enabledVirtualBackground:`, `setVirtualBackgroundBlur:`, `setVirtualBackgroundImage:`, `setVirtualBackgroundInferenceInterval:`, `setVirtualBackgroundMaskSync:`, and `isVirtualBackgroundEnabled`. It performs person segmentation and then blurs or replaces the background, and **installing it doesn't require a license key**.
+ Virtual background applies to the single shared camera capture pipeline in the process. It's a device-level setting that applies to all rooms at once. After a camera switch during the meeting or a reconnect, the SDK automatically re-applies the current configuration, so your app doesn't need to do it. For usage, see [Virtual background](/en/meeting/ios/advanced/virtual-background).
+ `SEADeviceType` adds `SEADeviceTypeHarmonyOS` (`8`) to identify HarmonyOS members.
#### Changed
+ The minimum OS requirement is raised from iOS 10.0 to **iOS 16.0**.
+ The `RTCEngineKit` dependency is upgraded to `3.1.0`, and the podspec's minimum dependency is raised from `>= 3.0.0` to `>= 3.1.0`. The virtual background inference engine `onnxruntime-c` is pulled in transitively through the `RTCEngineKit` podspec, so you don't need to declare it explicitly in your `Podfile`.
#### Fixed
+ Picks up the local preview fix in `RTCEngineKit 3.1.0`: with virtual background on, the local preview now shows the processed video, matching what the other side sees. Previously the local side could only see the raw camera video.
+ Picks up the fix in `RTCEngineKit 3.1.0` for video freezing caused by the pre-processing output buffer being released too early and the display buffer conflicting with writes of the next frame.

<Warning>
This release contains breaking changes: your project's `IPHONEOS_DEPLOYMENT_TARGET` and the `platform :ios` in your `Podfile` must be at least 16.0; otherwise the dependency can't be resolved. No existing public APIs or callback signatures of `MeetingKit` and `MeetingKitRoom` were removed or changed, so existing code doesn't need to be rewritten.
</Warning>

### [2.0.0] - 2026.08.12
#### Added
+ Added the meeting room instance class `MeetingKitRoom`, which carries all in-meeting capabilities: entering and exiting rooms, local audio, video, and sharing, chat and raise hand, host management, cloud recording, the waiting room, sub-meetings, sign-in, and room data queries.
+ Added the room event protocol `MeetingKitRoomDelegate`, which carries all in-room events.
+ `MeetingKit` adds `createRoomWithDelegate:` and `getRooms` to create room instances and query the rooms you have entered.
+ `MeetingKitRoom` adds `publishLocalVideo:` and `enabledSendAudio:` to control publishing of local video and audio per room.
+ `MeetingKitRoomDelegate` adds the `meetingRoom:onUserUpdate:` callback for updates to your own data and the `meetingRoom:onReceiveCustomMessage:action:userId:sessionId:nickname:` callback for room custom messages.
#### Changed
+ `MeetingKit` is narrowed down to a global singleton that keeps only login and logout, IM, meeting queries and scheduling, device lists, local capture preview, audio routing, and screen capture process integration.
+ `enterRoom:onSuccess:onFailed:`, `exitRoom:`, `callUser:onSuccess:onFailed:`, `requestOpenCamera:view:onSuccess:onFailed:`, `requestShare:onSuccess:onFailed:`, `sendRoomChatMessage:messageType:targetId:onSuccess:onFailed:`, `switchSpeaker:`, `enabledAudioModule:`, `startRemoteView:streamType:view:`, the `adminXxx` family, and the cloud recording, waiting room, sub-meeting, sign-in, room data query, and media configuration APIs move from `MeetingKit` to `MeetingKitRoom`.
+ `MeetingKitDelegate` keeps only two global events: `onAudioRouteChange:previousRoute:` and `onApplicationPerformance:cpuUsage:`.
+ The other in-meeting callbacks move to `MeetingKitRoomDelegate` and all carry the source room instance as the first parameter. For example, `onEnterRoom:userId:` becomes `meetingRoom:onEnterRoom:userId:`, `onUserMicStateChanged:micState:reason:` becomes `meetingRoom:onUserMicStateChanged:micState:reason:`, and `onReconnecting` becomes `meetingRoomOnReconnecting:`.
+ The `RTCEngineKit` dependency is upgraded to `3.0.0`, and the podspec's minimum dependency is raised from `>= 2.5.0` to `>= 3.0.0`.
#### Improved
+ The same account can create multiple room instances at once and enter multiple rooms. Each room's media and business state is independent, and member data for the same userId across rooms is isolated per room.
+ Camera capture and preview, audio routing, and screen capture are managed centrally by `MeetingKit` as shared device capabilities; whether they are pushed to a given room is controlled separately by that room instance.
+ `logout` exits and destroys all room instances before releasing resources, so your app doesn't need to exit each room one by one.

<Warning>
This release contains breaking changes. Your app must hold room instances through `createRoomWithDelegate:`, rewrite all in-meeting API calls, and migrate in-meeting callbacks to the new `MeetingKitRoomDelegate` signatures; otherwise the related APIs won't compile and the callbacks will no longer fire.
</Warning>
