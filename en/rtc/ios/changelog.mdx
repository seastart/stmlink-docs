### [3.1.2] - 2026.09.14
#### Fixed
+ Fixed the [onRemoteMemberAudioStatus:](/en/rtc/ios/api-reference/RTCEngineChannelDelegate#enginechannelonremotememberaudiostatus) callback attributing the speaking user to the wrong person with Wangsu media streaming: on this path the server doesn't send the connection ID, so `linkId` in [RTCStreamAudioModel](/en/rtc/ios/types#rtcstreamaudiomodel) is always `0`. Looking up the user by it used to hit the first match in the list, so when you did voice activation, the highlighted user was often not the one actually speaking. The SDK now resolves the user ID from the underlying connection and only falls back to the old `linkId` lookup when that fails;
+ Fixed `db` being set to `-60` (silence) instead of the entry being skipped when the statistics lacked a volume item: when the volume statistic was unavailable, `0` was used in the conversion, always yielding `-60` dB, so your app would misread "this statistic is unavailable this time" as "this person isn't speaking";
+ Fixed App Store uploads from your project being rejected with `ITMS-90171` and `ITMS-90166`: `RTCEngineKit.bundle` is a pure resource bundle, but the build output included a useless placeholder executable and the `CFBundleExecutable` key in `Info.plist`, which Apple flagged as "a resource bundle must not contain a standalone executable". Both are now removed at build time. After upgrading to this version, just re-archive and upload; your project needs no changes.

<Note>
The public APIs, callback signatures, and type definitions of `RTCEngineKit` are unchanged, so existing code needs no rewriting, and the minimum system requirement is still iOS 16.0. If you use Wangsu media streaming for voice activation, or your App Store uploads were previously rejected with the two error codes above, upgrade to this version.
</Note>

### [3.1.1] - 2026.09.09
#### Fixed
+ Fixed remote video being completely black after subscribing with SeaStart media streaming: remote video is dispatched by an index key of the form "channel\_userId\_trackId", and channel names and user IDs may themselves contain underscores. Splitting the key on underscores used to yield the channel name, so every frame was dispatched to a nonexistent user;
+ Fixed video from the second and later publishers rendering on the wrong user's view when a channel had multiple publishers with SeaStart media streaming: the server reuses the same media section to forward different publishers' streams in turn, so render bindings are now rebuilt by stream ID after subscription negotiation completes;
+ Fixed misplaced layer declarations for the high and low streams: the primary layer's `variant` and the secondary layer's `fallbackIds` used to be written to each other's [RTCEngineStreamTrackModel](/en/rtc/ios/types#rtcenginestreamtrackmodel), making the layer declarations received by the server unusable;
+ Fixed new media sections getting their own transport when the data channel was negotiated first and media sections were added later with SeaStart media streaming: the subscriber side now explicitly declares the BUNDLE and ICE policies to match the server's ice-lite single-port setup.
#### Improved
+ Person segmentation for virtual background now always runs on the CPU and no longer uses CoreML. Measured on iPhone XS Max / iOS 18.7.9 (720p@25fps, average over 300 frames): per-frame time dropped from 53.17 ms to 20.61 ms, `installVirtualBackground:` time from 1271 ms to 130 ms, process CPU usage from 172% to 63%, and memory from 83 MB to 58.6 MB. See [Virtual background](/en/rtc/ios/advanced/virtual-background);
+ Background blur now downsamples, applies a Gaussian blur, and then upsamples, cutting the pixels processed to 1/16 of before; image compositing now matches the Web, Android, and HarmonyOS clients;
+ With SeaStart media streaming, the low stream no longer gets its own published track. Instead, the primary and secondary layers are declared as two simulcast encodings on the same connection, and each layer applies its own scaling factor, maximum bitrate, and maximum frame rate.
#### Changed
+ With SeaStart media streaming, the subscription candidate layers are narrowed to only the layer you subscribe to. When the candidates included both the primary and secondary layers, the server forwarded both RTP streams in turn on the same output SSRC without rewriting sequence numbers, so the receiver kept treating packets as replayed, dropped them, and flickered between the two resolutions. The trade-off is that the server no longer falls back to the secondary layer automatically on a poor network; call `startRemoteView:trackId:view:` yourself to subscribe to the low stream as your scenario requires.

<Note>
The public APIs, callback signatures, and type definitions of `RTCEngineKit` are unchanged, so existing code needs no rewriting, and the minimum system requirement is still iOS 16.0. Projects using SeaStart media streaming should upgrade to this version directly.
</Note>

### [3.1.0] - 2026.09.08
#### Added
+ Added virtual background: `installVirtualBackground:`, `uninstallVirtualBackground`, `enabledVirtualBackground:`, `setVirtualBackgroundBlur:`, `setVirtualBackgroundImage:`, `setVirtualBackgroundInferenceInterval:`, `setVirtualBackgroundMaskSync:`, and `isVirtualBackgroundEnabled`. It blurs or replaces the background after person segmentation, and **installing it doesn't require a license key**;
+ Virtual background and the beauty filter work on the same shared camera capture pipeline. When both are on, the order is fixed: beauty filter first, then virtual background. For usage, see [Virtual background](/en/rtc/ios/advanced/virtual-background);
+ Added `SRTCDeviceTypeHarmonyOS` (`8`) to `SRTCDeviceType` for identifying HarmonyOS users.
#### Changed
+ The minimum system requirement is raised from iOS 10.0 to **iOS 16.0**;
+ CocoaPods integration adds the `onnxruntime-c` (`~> 1.24.0`) dependency. The SDK keeps only its undefined symbols, which your app resolves at link time; with manual integration, add `onnxruntime.xcframework` yourself.
#### Fixed
+ Fixed the local preview still showing the raw camera image after the beauty filter or virtual background was turned on, with only the remote side seeing the effect: the local preview now shows the pre-processed image, and returns to the direct system preview when both are off;
+ Fixed frozen video caused by the pre-processing output buffer being released too early, and by the display buffer and the next frame's write conflicting on the GPU;
+ Fixed concurrent access when installing, uninstalling, or toggling the render component and the virtual background component while the capture thread was rendering.

<Warning>
This is a breaking change: your project's `IPHONEOS_DEPLOYMENT_TARGET` and the `platform :ios` in your `Podfile` must be at least 16.0, or dependency resolution fails. No public APIs or callback signatures were removed or changed, so existing code needs no rewriting.
</Warning>

### [3.0.1] - 2026.08.14
#### Fixed
+ Fixed screen sharing failing to publish in `3.0.0`: the capture service now starts and keeps listening as soon as joining the channel succeeds, so the extension can connect when the user starts screen recording from the system panel, instead of missing the connection while waiting for `publishScreenRecord:`;
+ Fixed `-[RTCEngineKit stopScreenRecord]` only unpublishing without actually ending system screen recording; it again disconnects the extension to end the current recording.
#### Improved
+ Screen sharing is now split internally into a subscription layer and a publishing layer: joining a channel sets up the subscription so the capture service keeps listening, and `publishScreenRecord:` only expresses this channel's intent to publish. The current system recording ends when the last publishing channel unpublishes, and the capture service is released only when the last channel leaves;
+ `RTCScreenRecordStatus` is a process-level state and is reported to every channel the process has joined. To decide whether the local side is sharing, combine it with your own publishing intent rather than relying on this state alone.

<Note>
The call sequence is unchanged: present `RPSystemBroadcastPickerView` → receive `RTCScreenRecordStatusStart` → call `publishScreenRecord:YES`. Projects on `3.0.0` should upgrade to this version directly.
</Note>

### [3.0.0] - 2026.08.12
#### Added
+ Added the channel instance class `RTCEngineChannel`, which carries in-channel capabilities: joining and leaving the channel, user and channel data, publishing and subscribing to streams, sending audio, publishing screen sharing, custom streams, and more;
+ Added the channel event protocol `RTCEngineChannelDelegate`, which carries in-channel connection, user, message, audio, stream, and screen sharing events;
+ Added `createChannelWithDelegate:` and `getChannels` to `RTCEngineKit` for creating channel instances and querying active channels;
+ Added `publishScreenRecord:` to `RTCEngineChannel` to start and stop publishing the screen sharing stream per channel.
#### Changed
+ `RTCEngineKit` is reduced to a process-level singleton that keeps only initialization and destruction, channel instance management, IM (out-of-channel messaging), camera capture and preview, audio routing, screen capture process access, network speed test, and beauty filter rendering;
+ `joinChannelWithToken:`, `leaveChannel:`, `getMySelf`, `getRemoteUsers`, `publishLocalVideo:`, `startRemoteView:trackId:view:`, `enabledSendAudio:`, `setStreamMediaConfig:`, custom streams, and other in-channel APIs moved from `RTCEngineKit` to `RTCEngineChannel`;
+ `RTCEngineDelegate` keeps only four process-level events: `onAudioRouteChange:previousRoute:`, `onSpeedTestBegined`, `onSpeedTestUploadResult:downResult:connectResult:`, and `onApplicationPerformance:cpuUsage:`;
+ The remaining in-channel callbacks moved to `RTCEngineChannelDelegate`, and all carry the source channel instance as the first parameter. For example, `onJoinSucceed:userId:` became `engineChannel:onJoinSucceed:`, `onRemoteUserLeaveChannel:userId:reason:` became `engineChannel:onRemoteUserLeaveChannel:reason:`, and `onScreenRecordStatus:` became `engineChannel:onScreenRecordStatus:`;
+ `RTCStreamAudioModel.userId` and `RTCStreamReceiveModel.userId` changed from read-only to nullable and writable.
#### Improved
+ One process can create multiple channel instances and join multiple channels at the same time; user data, stream statistics, and rendering don't interfere between instances;
+ Camera, audio routing, ReplayKit capture, and beauty filter rendering are process-level shared capabilities managed by the engine. Screen capture starts when the first channel publishes and ends when the last channel stops publishing;
+ `-[RTCEngineKit destroy]` first destroys all live channel instances and waits for them to finish leaving, then releases process-level resources.

<Warning>
This is a breaking change. Hold channel instances through `createChannelWithDelegate:`, rewrite all channel API calls, and move in-channel callbacks to the new signatures in `RTCEngineChannelDelegate`; otherwise the related APIs won't compile and the callbacks won't fire.
</Warning>

### [2.5.10] - 2026.08.05
#### Changed
+ The `onReconnecting` callback gains a channel name parameter; the signature becomes `onReconnecting:`;
+ The `onDisconnected:errCode:errMsg:` callback gains a channel name parameter; the signature becomes `onDisconnected:reason:errCode:errMsg:`;
+ The `onCustomMessage:action:userId:sessionId:nickname:` callback gains a channel name parameter; the signature becomes `onCustomMessage:content:action:userId:sessionId:nickname:`.
#### Improved
+ Disconnect, reconnecting, and custom message events all provide the source channel directly, so you no longer need to infer it yourself with multiple channels.

<Warning>
This is a breaking change. After upgrading, update your implementations of the three callbacks above, or they will no longer fire.
</Warning>

+ Added the client type `RTCTerminalType`;
+ Added the stream event name `RTCEngineKitEventNameStreamsEvent`;
+ Added the client type `terminalType` and client description `terminateDesc` properties to the initialization configuration `RTCEngineConfig`;
+ Added `changeWithStreams:changeType:` for changing stream info;
+ Added a class method for initializing the RTC service, which lets you hold and manage the `RTCEngine` object yourself;
+ Added the `userModel` parameter to RTC service initialization;
+ Added the read-only properties `engineConfig` and `userModel`;

#### Changed
+ Removed the `changeType` operation type parameter from the existing user info change method;
+ Added the `delegate` parameter to the existing RTC service initialization method `initializeWithConfig`;
+ In the existing user info `RTCEngineUserModel`, the `sdkno` property changed to `linkid`, and the `sessionId` property changed to `sessionKey`;
+ The ID property in the room info object `RTCEngineRoomMode` changed to the `NSString` type;
+ Removed the `userModel` property from the `RTCEngineConfig` object;
+ The existing `sendMessageWithUserList:message:` method changed to `sendMessageWithUserIds:message:`;

#### Improved
+ Improved internal logic.
